## ★★★ 三处留痕(我改了口径 / 和登记不一致的地方)

### 留痕 1 · 指纹拼法是我自己定的,不是提交信息里那个

提交 `55088733` 的信息里写了两个 16 位数(engine `4595155d639f2d89` ·
configs `92ba8cb33a0a9799` → `2e90c3b9fe28774f`),
★★★ **但算这两个数的脚本没有入库**,拼法无从得知。
我试了 18 种常见拼法(文件集 × 三种拼接方式)**一个都没对上**。

→ 处置:**自己定一个写死在脚本里的拼法**(`FP_RECIPE`),跑前跑后用同一把尺子:

```
逐份 sha256;按仓库相对路径排序;每份拼成 '<path>:<sha256>\n';整串 sha256 后取前 16 位
```

★ 这一改**不削弱**「代码必须一字不差」那条:
代码那一条是用《V2题目指纹》里的**逐份 SHA-256 做逐份比对**过的(83 份全中),
比对一个汇总数更强。16 位数只是给人看的摘要。

### 留痕 2 · sanity check 换了池子,而且「改前」那一次是现跑的

`engine/bench_run_1029.main` 跑 sanity check 用的是 `data.full_universe().pool("ALL")`
**全池**;★★★ 本轮铁律是「只在研发池跑」,所以 `sanity_bah_1104.py` 用的是
**研发池 198 只 × 大+中口径**(和本轮 45 条链完全同池)。
★ 四项检查是结构性的(闸门 / 恒等式),换池不改变它们该不该成立。

★★ 另外:`buy_and_hold` 的 sanity check **在研发池上从来没跑过**
(1102 那一轮只出基准一,没出基准线套件),所以「改前」这一次是现跑的 ——
配置从 git `55088733^` 取(那时 `one_way_bps: 0.0`),engine 一个字没动。
判据直接 `import engine.bench_run_1029.sanity_check`,没自己抄一份。

### 留痕 3 · 登记里「改前 21 赢 / 22 输」是考卷的数,不是研发池的

★★★ 《手册 23》第三节把预言二的基线写成「改前是 21 赢 / 22 输」。
实测:**那是考卷(1,042 只)的数**;研发池(老池 198 只)1102 实测是 **22 赢 / 23 输**。
出处:`probe/exam_run_1102/考卷结果-1102.md` 里那张两列表(考卷 21/22 · 老池 22/23)。

→ 本轮铁律只许跑研发池,所以**可比的改前基线是 22,不是 21**。
两个数都在报告里报,判定用 22。
