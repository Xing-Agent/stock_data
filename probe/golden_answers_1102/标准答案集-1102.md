### 4.1 「基准一」—— ★★★ 只给 4 条冻，另外 6 条不冻

这是本次最重要的发现，**而且它不是我的判断，是仓库里已经登记在案的事**。

`probe/bench1_rerun_1031/degenerate_r_1031.json` 写着：

```

★基准一不可用的链数      = 35       ← ★★★ 45 条里有 35 条的基准一是坏数
★基准一数值已经爆掉的链  = 5 条，值分别是:

    技-10 持仓3天  → −5,256,921,595

```

**大白话：** 随机对照组里有几笔的止损价正好落在进场价上（差 3.55e-15，浮点尘埃），
1R 约等于 0 → 那一笔的 R 算出 1.75e14 → **一笔就把 50 个种子的均值毁掉**。
算出来的 −60 亿**不是一个数，是垃圾**。

**关键在于：怎么修还没拍板。** 那份 JSON 自己写着：

> ★待策略组拍板：「止损价 == 进场价」时 1R 等于多少 —— 这个没有定义。
> 剔掉 / 置 NaN / 用进场价当分母，**三种补法会改变全库每一个 R**。

所以：

```
★★★ 如果现在把这 35 条的基准一冻成「标准答案」，
    等你拍了板，这道检查会**全线 FAIL** ——
    而那不是「改坏了」，那是**我们自己要的改动**。
    一道会把「正确的修复」报成「回归」的检查，用两次就没人信了。
```

**我的做法：**

| 量 | 冻不冻 | 怎么办 |

| 基准一的**数值** | 只冻「能用」的 4 条（#1 #5 #6 #7） | 另外 6 条留空，标 `待拍板` |

## 5 · 容差怎么定

```
整数 —— 必须完全相同，零容差
   笔数 · 代码数 · 合格进场信号数 · 退化笔数 · 种子数
   理由：这些量差 1 就是行为变了，没有「浮点误差」一说。

浮点 —— 相对误差 1e-9
   每笔净R · 每笔毛R · 总R · 最大单笔R · 持仓天数中位数 ·
   基准一（仅那 4 条能用的）· 对照笔数偏差
   理由：同样的代码、同样的 50 个写死种子，本来就该给同样的结果；
        1e-9 只容忍浮点累加顺序的差别，别的什么都不容忍。

比较写法（★ 避开 0 附近除零）：
   通过  ⟺  |a − b| ≤ 1e-9 × max(1, |b|)
   ★ 用 max(1,|b|) 而不是 |b|：有些量（基准一）本身就在 0 附近，
     纯相对误差在那里会炸。
```

### ★★ 一个要事先说清的坑：`对照笔数偏差` 会「跳」

这个量**是确定性的**（50 个写死种子，同代码必同结果），所以可以冻。
但它背后有一个**校准循环**（调随机触发率，调到对照笔数和真链笔数相差 ±5% 以内，最多 6 轮）。

**后果：** 触发率上一个 1e-12 的差别，可能让循环**多跑或少跑一轮**，
于是对照笔数整笔整笔地跳，偏差一下就超过 1e-9 很多。

★ 所以这个量**失败时是「大幅跳变」而不是「略微超差」**。
这不是误报，是真的变了 —— 但失败报告里得写明白这一层，
不然下一个人看到「偏差差了 0.004」会以为是浮点问题而随手调大容差。
