## 二 · R 的分母锁死首仓初始风险

**代码**:`engine/checks/r_denominator_lock.py`

### 口径(已落成可调用的函数,加仓落地时直接用)

```
1R = |Entry₁ − InitialStop₁| × Shares₁
Final R-Multiple = [ Σ(Exit_i − Entry_i) × Shares_i − 总费用 ] / 1R_initial
```

`one_r()` / `final_r_multiple()` —— ★ 后者**不会**根据 legs 重算分母,
分母由调用方传进来。这就是「严禁随加仓动态改变分母」在代码上的落点。

### 两条理由都实测量化了

| 理由 | 实测 |
|---|---|
| ① **稀释** | 同一笔加仓三次的顺风交易:锁死首仓分母 = **+27.00R**;分母跟着加仓放大 = **+9.00R** → 被稀释成 **33%** |
| ② ★★ **除以 0** | 止损抬到保本(stop = entry)→ 名义风险 0 → `one_r()` 抛 `RDenominatorError`,★ **不是静默返回 nan** |

★ 第二条**不是「可能不准」,是没有定义**;而且它在本仓库是**必然**发生,不是偶然 ——
我们几乎每条链的 `trailing_stop` 里都有「保本」那一级
(`move_to_breakeven` / `move_stop_to_breakeven`)。

★ 还钉了一条容易漏的:止损抬到进场价**之上**时 `|entry − stop|` 仍为正、算得出,但那是**负风险**。
→ 所以分母必须**锁死首仓初始止损**,"挡一下非正数"是不够的。

### 现状已核实(不是推测)

`engine/chain.py` 的 `_close()` 用的是
`risk = abs(p["entry"] - p["init_stop"])` —— 取的是 **init_stop**(首仓初始止损),
**不是** `p["stop"]`(当前止损)。★ 所以引擎口径原来就是对的,本次是把它**锁上**。

闸做三件事,全部 ✅:
1. 读 `chain.py` 源码:必须有 `init_stop` 那一行,且不许出现 `abs(p["entry"] - p["stop"])`。
2. **双侧判定还在**:`RATIO_HI / RATIO_LO = 0.9 / 0.01`(`engine/run_declean_1030.py`)—— 已确认未被改动。
3. **真实流水 183 个文件 / 146,991 笔**:`risk_per_share` 逐笔等于 `|entry_price − initial_stop|`,0 笔不符。

其中 **138 条链**有笔子落在两头(>0.9 或 <0.01)→ 这些链按口径**不用 R**,改用每笔收益率 %。
★ 这不是 bug:技-12 / 技-2 的原著就是明确不设止损的。

**反向自测**:把 `chain.py` 的分母改成当前止损(改副本,不动原文件)→ 闸 FAIL,抓到 3 条。

★★ Lin 拍板时改了我提的措辞,**这个改动比补这一行本身重要**:
我原来提的是「基线链定义,等价于不设止损」—— ★ 那句话**读起来像某本书里的定义**。

trailing_stop:
  type: none
  source: >-
    ★ XING 定义(不是原著)。buy_and_hold 是我们建的基线链,
    它的定义就是「买入后不做任何离场动作」,所以移动止损明确为无。

## 五 · ★★★ 同一个槽位已知有几种写法

> **★ 写检查的人第一件事就该读这一节**(包括我自己、包括下一个 agent)。
> 代码里的同一张表:`engine/checks/four_slot_complete.py` 顶部,
> `engine/checks/run_all.py` 的 docstring 里有指针指过来。

**病根一句话:同一样东西有两种写法,而检查只认了一种。**
这一类 bug 今天已经发生 **6 次**。

| # | 同一样东西 | 写法 A | ★ 写法 B(容易被漏掉的那个) | 后果 |
|---|---|---|---|---|
| 1 | 用户面禁止字段 | 英文键 `score` / `sharpe` / `win_rate` | ★ **中文键** `审校分` / `夏普` / `胜率` | 第一版闸在我们自己的产物上**几乎拦不住任何东西**(已修:`user_facing_ban._ZH_ALIASES`) |
| 2 | 交易流水文件 | 文件名带 `ledger` | ★ `ledger` 在**目录名**上:`engine/ledgers_*/*.csv` | `*ledger*.csv` 这个 glob **一个都扫不到** |
| 3 | 中文路径 | 原样 | ★ git `quotepath` 转义成八进制 | 路径对不上 → 用 `git -c core.quotepath=false` |
| 4 | 初始止损 | `initial_stop`(技-* 共 41 份) | ★ **`stop_init`**(七个大师配置) | 只认 A → **误报 6 个大师配置「缺止损」** |
| 5 | 移动止损 | `trailing_stop` | ★ **`stop_trail`** | 同上 |

| 6 | 模块的两种跑法 | 单跑 `python3 engine/checks/X.py` | ★★ `run_all.py` 里跑(`module_from_spec`,**不注册 `sys.modules`**) | 见下 |

### ★★ 第 6 条:「两种跑法只测了一种」

`engine/checks/run_all.py` 的 `_load()` 用 `importlib` 的 `module_from_spec` 加载,
★ **不往 `sys.modules` 注册**。而 `@dataclass` 求值时要回查
`sys.modules[cls.__module__].__dict__` → 这里查到 `None`,炸成:

```
AttributeError: 'NoneType' object has no attribute '__dict__'
```

★★ **而单跑那个文件时完全正常** —— 所以只测单跑的话,这个 bug 会一路活到 `run_all.py`。

**两条结论(已写进代码注释)**:
1. 新检查里**不要用 `@dataclass`**,用 `collections.namedtuple` 或普通 class
   (实例:`engine/checks/r_denominator_lock.py` 的 `Leg`)。
2. ★★ **新检查必须两种跑法各跑一遍**:
   ```
   python3 engine/checks/<名>.py        ← 单跑
   python3 engine/checks/run_all.py     ← 在 run_all 里跑
   ```
   只测一种就是这一类 bug 的第 7 次。

★ `run_all.py` 的 `_load()` **故意没改**成注册进 `sys.modules`:
改了会影响已有 13 个检查的加载语义,收益只是让 `@dataclass` 可用 —— **不值**。
原因已写在那个函数的注释里。

### ★ 这一节真正的意思

**第 4 / 5 / 5b 三条本质是同一件事**,而它们**分三次**被踩到(两次由 Lin 手跑踩到、
一次由本次的闸踩到)。★ 也就是说:别名清单**不是写完就完了的东西**,
它是每次写新检查都要重新过一遍的**清单**。
★ 所以新槽位 `add_on` 的别名(`addon` / `pyramid` / `scale_in` / `加仓` …)
是**第一天就备齐的**,不是等误报了再补 —— 而且自测里逐个别名各跑一遍。

  → **收益不值这个风险**,所以走闸,不走 `adapt()`。

1. 现在 **0 份**配置有 `add_on`,这道闸唯一能挡的是**将来有人新写一份带 add_on 的配置**
