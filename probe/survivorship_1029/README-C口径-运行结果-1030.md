# C 口径 · 运行结果 · 2026-10-30

> **三秒版:C 口径没解决可比的问题。老池 300 只的「小盘档」本身就是全市场成交额排 2,000–6,000 名的票,成交额前 2,000 的地板装不下它们,修好所有 bug 后小盘档也只进来 36 只。**
> **根子上的矛盾:想要「每年约 1,000 只」又要「装下老池 300 只」,做不到 —— 小盘那一带有 4,000 只,抽 330 只只覆盖 8%。**

## 一 · 产出(按原脚本原样跑的)
- `pool_C_2015.csv … pool_C_2026.csv`、`pool_C_ALL.csv`(11,880 行)、`pool_C_对照.csv`
- 两道硬闸都过了;ETF 名单用了 CMES 的 5,206 个;每只都匹配到了段
- **原脚本的对照结论(252 只里 180 进、72 出)不能用**,原因见第二节
- 另给 `pool_C_对照-修正版.csv`:老池 300 只逐只列出档位、历年成交额排名、三种口径下进没进

## 二 · 原脚本的 5 个问题

| # | 问题 | 后果 |
|---|---|---|
| 1 | **每档取前 330,不是整档** —— 2,000 只三等分是每档 667,只取前 330 | 排名 331–667、998–1,334、1,665–2,000 的票整段跳过(CHRW 第 381 名、ORI 第 1,212 名就这么掉的) |
| 2 | **优先股规则误杀** `[A-Z]{2,5}P[A-Z]` | JNPR、PFPT、GRPN、EXPR、FRPT、HAPN 被当成优先股剔掉。这批数据里优先股写作小写 p(如 ABCpA),规则可以改成「代码里有小写字母」 |
| 3 | **ETF 名单按代码剔** | ELV、HHH 被剔(这两个代码以前是 ETF);上次已经提过 |
| 4 | **对照只比代码,不比公司** | CBRE、RITM、ELV、HHH、XPRO、WKC、FWONA 等 7 只其实在池里(用旧代码 CBG、NRZ、ANTM……),被算成掉出 |
| 5 | **对照的老池名单不对** | 读的是 `pilot_300/` 的文件夹:漏了从 pilot_50 来的 50 只,还把 `selection`、`reviews` 两个文件夹当成了股票。完整名单在 `pilot_300/manifest.csv`(300 只,大/中/小各 100) |
