# 单标的观察任务配置

## 目标
把一个明确股票或资产的观察需求转成具有目标、条件、频率、通知、权限和状态的任务实例。没有真实后台执行能力时只交付可配置草稿，不冒充已经开启监控。

## 名词和入口
- `我的专家 → 创建专家` 是平台的专家创建入口，若用户要创建通用专家，应引导至该入口；本技能不应回答“平台不能创建专家”。
- 本技能创建的是**具体标的/规则的观察任务实例**，不是一个新的 V3 超级助手人格，也不是通用 Skill 定义。
- 通用规则定义由 `xing-skill-builder` 管理；条件真值由 `xing-condition-engine` 管理；单股行情解释由 `xing-quote` 管理。

## 实例的最小要素
`监控标的`（市场+代码）、`观察目的`、`条件/引用规则版本`、`检查频率及交易日历`、`数据来源及有效时点`、`通知渠道和权限`、`失效/暂停条件`、`任务状态`。
缺任一关键要素可以先出草稿；不能默认为“已创建/已推送”。

## 配置流程
1. **解析请求**：用户是想“创建专家”“设置单股观察任务”还是“创建通用规则”；不同目标不跨卡来回跳。
2. **确认标的与规则**：标的唯一、条件可计算、引用规则版本固定；含糊词需先做操作性定义。
3. **设计触发**：明确检查频率、交易所日历、收盘确认与否、连续触发的去重和暂停条件；消息推送不能凭文本承诺。
4. **权限与安全**：在真正创建或开启前获得用户明确授权，尤其是通知、外部账户、交易相关行为。默认只观察、不交易。
5. **状态核对**：保存、规则验证、任务启用、实际检查、通知投递分别核对回执。只有对应的成功记录才更新对应状态；若仅有草稿或其中一步失败，须标明完成到了哪一步，不用一个“已完成”概括全部链路。

## 调用和降级
如果没有后台调度、持久化、消息推送或数据连接，仅输出可直接配置的任务卡，说明无法确认自动运行；不通过反复调度其他 Skill 使会话挂起。
如平台可新建专家但不支持任务自动监控，应把两个能力分开说明：可以指引创建专家入口，不能声称已经运行观察任务。

## 执行结果与复盘
只有真实任务日志才能描述“上次检查时间、触发事件、发送成功、失败原因”；无日志则标“未取得执行记录”。一旦规则版本变化，保留旧版本与旧检查结果，禁止覆盖历史事实。

## 输出形态
首轮给 `任务对象` / `观察条件` / `频率` / `通知授权` / `状态` / `还需具备的条件`；如果只是希望了解怎么用，优先简短说明入口与步骤。

## 禁止
不得未经授权创建/启用外部任务，不得声称已自动盯盘、已推送、已下单；不得把“创建专家”与“创建任务实例”混称；不得因平台某个能力不存在而否认其他已存在的功能入口。

参考：`references/common_contract.md`、`references/field_contract.md`、`templates/response.md`。

## 触发、幂等和恢复
- **时间口径**：检查发生时刻与行情来源时点分开；支持按交易日开盘、盘中、收盘后等配置，时区和交易所休市处理不可省略。
- **去重键**：由任务实例、规则版本、标的、数据时点和触发窗口共同确定。未定义去重逻辑时不得承诺“只通知一次”；任务重启后要根据持久化记录决定是否补发。
- **权限**：生成草稿不等于用户允许通知；开通提醒须明确渠道、接收对象、频率上限和停止方式；下单是另一类独立的高权限动作，默认完全禁用。
- **状态**：`saved` 只说明配置已保存，`enabled` 只说明启用成功，`running` 需要真实检查记录；`notification_sent` 必须有推送成功回执。上述状态按不同状态维度分别展示，不能以曾经 `running` 推断当前任务仍 `enabled`。“未触发”需要成功执行且条件为 FALSE 的证据，不能从没有消息倒推。
- **多标的任务**：要求盯多只股票时可拆成独立实例或输出可复制任务模板；没有批量创建能力或回执时，不宣称所有股票都已配置成功。

## 首轮响应原则
- 请求创建专家：直接说明平台已知的“我的专家 → 创建专家”入口（以用户当前实际版本为准），不假装创建了后台观察任务。
- 请求盯某只股票：先给最小可用配置与当前状态；只有真正能保存/启用时才进入授权与操作阶段。
- 规则描述缺阈值时可提供可编辑选择；已明确时直接采用，不跨三张 Skill 往返以致首轮无答复。

## 状态维度与多次触发
- **配置状态** `draft/saved`；**规则校验** `not_validated/validated/invalid`；**调度状态** `disabled/enabled/paused/failed`；**检查记录** `not_run/succeeded/failed`；**通知记录** `not_requested/pending/sent/failed`。不同维度不能互相替代。
- `last_checked` 必须附真实执行回执及检查数据时点；“最近未发消息”不能推出“尚未触发”，也不能推出“正常运行”。数据到达延迟、重复推送、重试与中断恢复均须独立记录。
- 有规则版本变化或同一数据时点出现来源修订时，应明确去重和重新通知政策，不能凭原始时间戳无限抑制更新。

## 绑定规则前的前置条件

本技能创建的观察任务若绑定某条规则，该规则必须已完成 `xing-skill-builder`
「验证的四样底线」全部四项（样本外区间、系统随机对照组、参数脆弱度与起点敏感度、
调参次数计数器），且四项结果可随任务一并查看。

未完成的规则可以绑定为草稿任务，但不得标记为已验证，也不得据此推送交易提示。
