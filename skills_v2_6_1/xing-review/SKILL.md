# 持仓复检与投资逻辑核查

## 目标
针对用户实际持仓，分别判断原始理由是否仍成立、证据有哪些变化、风险暴露是否扩大，以及下一步应观察哪些条件。协助用户独立判断，不用猜测代替事实。

## 边界
- 只读取用户明确提供或已授权读取的持仓；若无成本、数量、买入理由，直接交付初步核查框架，不编造持仓。
- 亏损不自动等于投资理由失效；盈利也不自动等于理由成立。成本价只表示个人损益参考，不自动形成技术支撑或止损。
- 不将一般股票基本面研究误路由为“用户持仓复检”；若用户请求筛选新股票，应交 `xing-screener`。
- 能拿到有来源的最新信息时可辅助判断；拿不到则清楚划分“当前证据”和“用户提供的历史事实”。

## 五步复检
1. **持仓事实**：标的、市场、仓位/成本/持有期限、所处账户、决策时间。缺失字段标未知。
2. **原始逻辑**：以用户实际表述为准，分成业绩、估值、事件、趋势、行业或组合配置等可检验假设；用户未讲明时不替其编买入理由。
3. **证据变化**：逐条对照可查证的新信息，标“仍支持 / 削弱 / 已证伪 / 未核实”，附截止日。
4. **风险与约束**：区分公司风险、行业/宏观风险、流动性和个人资金期限、集中度、潜在最大承受损失；不存在可验证值时不算精确风险概率。
5. **条件分支**：写清继续观察、需要重新评估、原假设被证伪的触发条件，分开事实条件和用户决策。

## 首轮响应纪律
先按现有信息完成初步复检，再最多询问 3 个真正缺失且决定判断质量的问题：通常是原买入逻辑、资金期限、风险约束；若已给，不能重复询问。面对焦虑或急跌请求，先给目前确认的风险事实和可执行的复核清单，不以问卷挡住第一轮答案。

## 计算纪律
- 只有取得有效持仓数量、**成本口径和当前估值时点的价格**并校验币种、拆分与汇率后才计算浮盈亏；分红、拆分、手续费与税务须标明是否计入。
- 风险提示不声称未来收益率、止损有效性、后续必然反弹，不给未经证实的资金面和技术关口。
- 如存在真实的 Agent 日志，只复核指定实例、指定规则版本与执行记录；不可编造成套历史绩效或全局胜率。

## 输出结构
`持仓事实` → `原始逻辑与最新证据` → `关键风险` → `条件触发与复检项` → `未知事项`。事实与条件分开。必要时将仓位集中度和持有期限列为个人风险因素，不替用户做最终交易决定。

## 禁止事项
未经授权修改仓位；把亏损当作必须止损的证明；把一个股票的价格趋势写成公司价值结论；直接判定用户应该买、卖、加仓或清仓；在没有原始数据时做精确压力测试。

参考：`references/common_contract.md`、`references/field_contract.md`、`templates/response.md`。

## 不完整持仓与事件压力
- 已知标的但未知数量/成本时，可以依据真实标的与证据做初步研究；不能计算仓位占比、具体盈亏金额与家庭现金流影响。
- 已知“跌了 20%”仍不能推断买入价、持股数、原始买入逻辑或亏损原因；先明确价格回撤与个人账面亏损不是同一口径。
- “止损线”“失效条件”“资金期限”应分类：可用市场数据核验的客观事件、用户自定风险预算、尚未设定的观察假设，三者不能互换。
- 消息或政策对持仓的影响须给传导链和反证因素，不以单条新闻的标题代替公司订单、营收或财务影响的验证。
- 有多个账户、股种、交易市场或复权事件时，不先合并成本；只在同币种、同口径且用户授权下进行可审计的组合统计。

## 事件与价格变化的分离
- 用户反馈股价大跌并希望复检时，先列出可能影响持仓的公司、行业、市场因素与反证，不能仅由跌幅反推出订单恶化、财务恶化或原投资逻辑失效。
- 实时新闻、公司公告、实际财务结果和市场传言按各自来源等级记录；没有查到信息时直接标未核实，不填虚构“最新事件”。
- 用户要求量化组合损失时，除证券级数据外，还须处理账户币种、汇率时点、不同市场交易阶段和多笔买入成本；缺少任何关键项时只报告已知区间或需核实项。
