# 个股行情解释

## 目标
围绕一个明确标的，将可信行情整理为可复核的价格与交易状态解释。先做行情时点校验，再做结构说明。只在具备有效数据时进行指标计算或结论判断。

## 适用与排除
- 适用：询问某股票/指数今天的走势、近期变化、价格位置、量价关系、K线结构和观察条件。
- 纯问某个时点的价格：由直接报价能力回答，不必触发本技能的完整研究链。
- 讨论实际持仓是否继续持有：交由 `xing-review`；批量找股票：交由 `xing-screener`；具体技术体系的完整判断需经已安装且可用的技术分析能力。
- 标的或证券市场含混时，先明确市场与代码，不能凭名称自动确定。

## 硬性执行规则
1. 必须先校验标的、交易市场、行情时间、交易阶段、币种和周期。不同周期/复权口径不得混算。
2. 区分盘中、正式收盘、盘前盘后；无法确定是否收盘时不得称“今日收盘”；盘后/盘前价格不是常规时段收盘价，不得与当日常规交易涨跌幅混称。
3. 涨跌幅的基准必须明确；只有同一标的、同一币种与调整口径的当前价及前收盘价均有效、前收盘价大于零时，才计算 `(当前价-前收盘价)/前收盘价 × 100%`。不同市场、不同标的、不同价格调整口径或不属于同一交易基准关系的快照不得拼接。正常的日涨跌幅可比较当前有效交易阶段的价格与**该市场上一有效交易日的正式前收盘价**，两者日期本来不同；盘后价格与日内价格须标明各自阶段及相应基准。
4. 没有完整且同频率的 OHLCV/K 线序列时，不得声称突破、站稳、跌破某均线、金叉、放量或历史新高；“突破 N 日新高”必须明确比较 N 根此前已完成 K 线的最高值还是含当前 K 线的区间高点，盘中突破不能自动表述为收盘确认。
5. 描述“支撑/压力”必须说明取法与数据窗口；无法验证就只能列为观察假设，不输出精确价位。
6. 若行情工具失败，最多在可用能力内尝试一次替代来源；仍失败则结束取数，交付已知条件和明确缺口，不得进入循环。
7. 绝不声称“已经自动盯盘、设置提醒、已经下单”。如需规则配置，转至 `xing-agent-builder`。

## 输入处理
必需：标的（市场+代码或可唯一确定的名称）；用户所关心的时间段。若用户未给时间段，可先用最近**已验证**数据并注明实际时点；不得默认这就是当前实时行情。
可选：成交量、OHLCV、前收盘价、基准指数、复权、用户重点关注的价格或事件。

## 响应流程
1. 首句写“对象与数据截至时间”以及是否有可靠行情。
2. 展示经确认的价格、涨跌和量能等客观事实；缺失项目不补零。
3. 只在适用数据齐备时，说明价格在所选观察窗口中的位置、量价是否支持假设；分开事实与解释。
4. 给两种以上条件情景（如站上/失守何种经计算的位置），不写成确定交易建议。
5. 简短列出最影响判断的缺口及下一步可验证条件。

## 回复规格
优先使用四段：`行情状态` / `已验证变化` / `条件观察` / `数据限制`；普通问题控制在 250–450 字，除非用户要求展开。
禁止：无来源“目前股价…”；无数据“主力资金正在流入”；单靠下跌幅度断言低估；在所有行情缺失时硬给点位。

## 自检
回复前确认：证券市场唯一吗、报价时间清楚吗、交易阶段清楚吗、数据口径一致吗、存在未经验证的技术指标吗、是否误入其他 Skill 职责？

参考：`references/common_contract.md`、`references/field_contract.md`、`templates/response.md`。

## 时点与数据冲突处理
- “今天”按交易所所在地的交易日解释，明确北京时间、纽约时间等时间差；节假日与尚未开盘不能用上一交易日的价格冒充今日收盘。
- 同一标的多个来源的快照冲突时，先列出各自时点和口径；无法消解时不拼接计算，说明冲突或仅引用一份完整、可靠来源。
- 企业行动（拆股、分红、复权）可能改变跨期价格可比性；计算区间涨幅前校验前后口径。
- 用户问“为什么上涨/下跌”时，区分同时发生的已核验事件与因果证据；仅时间相关不能认定事件是唯一原因。
- 输出必须区分 `数据截至` 与 `答复生成时间`；不可用“现在”代替数据时间。

## 涨跌比较的适用关系
- `current_price`：所选报价时点的有效价格；`previous_close`：该报价对应的上一有效常规交易日正式收盘价（如除权除息需同口径调整）。两者可以来自不同日期，但必须属于**同一标的、同一交易市场、同一调整口径、明确对应的前收盘基准**；不能将相隔数日的任意历史价硬当“前收盘”。
- 非常规时段报价需单独标记盘前/盘后及比较基准；缺少明确基准时只报告报价事实，不输出日涨跌幅。
- 有连续历史数据时，按成交所在交易所的日历确认有效交易日，不能拿自然日或周末凑成 N 根 K 线。
