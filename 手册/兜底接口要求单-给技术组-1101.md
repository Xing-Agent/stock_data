# 兜底接口要求单 · 给技术组

> **大白话入口：** 用户问大师一个问题，如果我们自己答不了，就转给外部模型（Gemini）来答 —— 这叫「兜底」。
> **技术组实现这条路；判据和文案是策略组写的（就是这一份）。**
>
> 版本：v1 · 2026-11-01 · 维护：策略组 · 实现：技术组

---

# 第一页 · ★★★ 全份只有一句话最要紧

```
★★★ **兜底不是「转接」，是「转接 + 过滤 + 标注」。**
```

## ★★ 为什么（★ 三句话）

```
★ 我们的大师卡有硬边界:不给方向 · 不给我们合成的评分 · 不给我们合成的排序 ·
  出处必标 · 不给无分母的概率。
★★★ **但外部模型不守我们的规矩。** 一个问题落到它那里,★ 它会很乐意给方向、
   给评分,★★ 还会编出处 —— ★★★ 实测:它承认自己把 **6 条引文「伪造」**成了原著原句。
★★★ → 所以如果只是「接上」,★ 我们的红线就从兜底这个口子**全漏出去了**。
   ★★ 而用户看不出哪句是我们的、哪句是它的 —— **他只看到「XING 说……」**。
```

★ 「接通了」在工程上看起来就是通了 —— ★★★ **但通了不等于安全。**

# 第二页 · 五道卡口

| # | 卡什么 | 不做会怎样 |
|---|---|---|
| ★★★ **1** | **什么情况才兜底**（门槛） | ★ 变成「答不上来就甩给它」，★★ 把本该如实说的也转出去 |
| ★★★ **2** | **全文标第 ⑤ 档** | ★ 用户把它的话当成我们验过的 |
| ★★★ **3** | **过同一道红线检查** | ★★★ **我们的红线从这个口子全漏** |
| ★★ **4** | **兜底失败要有出口** | ★ 转圈、超时、或者编一个 |
| ★★ **5** | **留痕** | ★ 算不出完整度，★★ 也查不了是哪一次出的问题 |

# 第三页 · 第 1 道 · 什么情况才兜底

## ★★★ 先分类，再决定（★ 四类里只有一类兜底）

```
用户问了一个我们答不上来的问题
        │
        ▼
★★★ 先判这是哪一类(★ 按顺序判,★★ 命中就停)
        │
   ┌────┼────┬────────┬──────────┐
   ▼    ▼    ▼        ▼          ▼
【甲】 【乙】【丙】   【丁】
没数据 红线 这一版    真的不会
       挡的 还没做
   │    │    │        │
   ▼    ▼    ▼        ▼
 ❌    ❌    ❌      ★★★ ✅ **只有这一类兜底**
如实说 如实说 如实说
```

## ★ 四类怎么判（★★ 要能写成代码）

| 类 | 判据 | 对用户说什么 | 兜底吗 |
|---|---|---|---|
| **甲 · 没数据** | ★ 问题需要的字段在「已知缺口表」里（★★ 两张大师卡最后一节各有一张） | 「这个数平台现在算不出来」★ 并说明缺哪一样 | ❌ |
| **乙 · 红线挡的** | ★ 问题命中红线模式（★★ 见第四页那张表） | 「这类问题我们定了不答，原因是 ××」 | ❌ |
| **丙 · 这一版没做** | ★ 问题落在已登记的「本版未做」清单里 | 「这一版只覆盖 ××，×× 我们还没做」 | ❌ |
| ★★★ **丁 · 真的不会** | ★ 以上三条都不命中，★★ 而大师卡里没有对应的分析流程 | ★★★ 先说「这个超出我们编码过的范围」，★ 再给兜底回答 | ★★★ ✅ |

## ★★★ 两条不许违反（★ 来自 V3 规格 §6.1）

```
★★★ ① 不许把**用户自己的设置**说成**我们的政策**。
★★★ ② 反过来也不许 —— 不许把**我们的限制**说成「你没设」。
★★ 这两种说法听起来差不多,★★★ 但归属完全不同 —— **归属错了就是在骗他。**
```

# 第四页 · 第 3 道 · 红线检查（★★★ 最容易被忽略的一道）

> ★ 这一道要**对兜底回来的内容再跑一遍**，★★ 和对我们自己输出跑的是**同一道**。
> ★★★ 参考现成实现的思路：`engine/checks/user_facing_ban.py`（★ 含 32 条中文别名）。

## ★★ 要拦的五类（★ 每类都要带中文别名，否则在我们自己的中文输出上几乎拦不住）

| 类 | 英文模式 | ★★★ 中文别名（★ 必须一起拦） |
|---|---|---|
| ★★★ **无分母的概率** | `confidence`, `probability`, `likely`, `odds` | **置信度 · 确信度 · 把握 · 大概率 · 很可能 · 八成 · 多半 · 概率较高 · 胜率较大** |
| ★★★ **我们合成的评分** | `score`, `rating`, `grade` | **综合评分 · 综合得分 · 健康度 · 匹配度 · 强度分 · 审校分 · ×× 分（0–100）** |
| ★★★ **方向性建议** | `buy`, `sell`, `should buy`, `target price` | **该买 · 该卖 · 建议买入 · 建议减仓 · 可以进场 · 目标价 · 看多 · 看空** |
| ★★ **邀功归因** | `avoided`, `saved you` | **为您避免 · 帮您省下 · 成功躲过 · 挽回损失 · 幸亏** |
| ★★ **拟人化意图** | — | **主力 · 庄家 · 洗盘 · 诱多 · 吸筹 · 派发**（★ 这一类**可以给偏好开关**，默认拦） |

## ★★★ 拦到了之后怎么办（★ 三种处理，不是一种）

| 情况 | 处理 |
|---|---|
| ★ 整段核心就是被拦的东西（★★ 比如整段在说「该买」） | ★★★ **整段不透给用户**。★ 说「这个问题的回答含我们不能转述的内容，所以不给」 |
| ★ 只是某一句带了被拦的词（★★ 但主体内容有用） | ★★★ **拦掉那一句，其余透给用户**，★ 并在那一处标「★ 此处原文含我们不转述的表述，已删」 |
| ★★ 评分类（★ 它给了「87 分」） | ★★★ **把分数拿掉，保留它的理由文字** —— ★ 理由有信息量，分数没有 |

## ★★★ 一条例外（★ 不要拦过头）

```
★ **原著定义的计分不许拦** —— ★★ F-Score 的 9 分、RS Rating 的 80 分、
  Piotroski 的 7 分、Altman Z 的 1.81/2.99 —— ★★★ 这些是**原著自带的**,不是我们合成的。
★ 拦的判据不是「出现了数字和分」,★★★ 是「**这个分是谁合成的**」。
★★ 实现建议:维护一张「允许的计分白名单」,★ 白名单里的照过。
```

# 第五页 · 第 2 道（标注）· 第 4 道（失败出口）· 第 5 道（留痕）

## ★★★ 第 2 道 · 全文标第 ⑤ 档

```
★ 标注原文:「**外部模型回答 · 未经我们测试**」
★★★ 三条要求:
   ① ★★★ **界面上不许折叠** —— ★ 和出处标注同一条规矩
      (V3 规格原话:「归属标注在界面上不能被折叠掉。它不是脚注,它是课。」)
   ② ★★ 标注必须在**内容前面**,不是后面的小字
   ③ ★ 如果一个回答里**一半是我们的、一半是兜底的** →
      ★★★ **逐段标**,不许整篇只在末尾标一次
```

## ★★ 第 4 道 · 兜底失败要有出口

| 失败情形 | 处理 |
|---|---|
| ★ 超时 | ★★ 阈值 **20 秒**（★ 第一版，待实测调）→ ★★★ 直接说「这个我们答不了」 |
| ★ 它拒答 | ★★ **不重试**，直接走同一个出口 |
| ★ 它答跑题（★★ 答的不是问的） | ★★★ **不透给用户**，走同一个出口 |
| ★ 调用出错 | ★★ **最多重试 1 次**，★★★ 再失败就走出口 |

```
★★★ 出口的原话:「**这个超出我们编码过的范围,而外部查询这次也没拿到有用的回答。**」
★ 不许转圈("我再试试"),★★ 不许编,★★★ 不许改口说成「这类问题我们不答」
   —— ★ 那是把工程失败说成红线,**归属错了**(第三页那两条)。
```

## ★★ 第 5 道 · 留痕（★ 这是算完整度的唯一依据）

```
★ 每次兜底记一条,字段:
   时间戳 · 用户问题原文 · ★★ 判给了哪一类(甲/乙/丙/丁)· 是否真的兜底 ·
   兜底回答原文 · ★★★ **第 3 道拦掉了什么**(拦了哪一类、拦了几处)·
   最终给用户看到的内容 · 耗时
★★★ 这张表不许只记成功的 —— ★ 失败、拦掉、走出口的**全都要记**。
```

# 第六页 · 完整度怎么算

```
★★★ **完整度 = 我们自己答的 ÷ 总问题数**

★ 跑一轮(比如 100 个问题),分三桶:
   ① **我们自己答的**              ← ★★★ 这个比例就是完整度
   ② **兜底答的**(标第 ⑤ 档)       ← ★★ 应 ≤ **20%**
   ③ **两边都答不了**(如实说不会)  ← ★★★ 这一桶**不是失败,是诚实**
```

## ★★★ 怎么读这个数

```
★★ 兜底超过 20% → ★★★ **不是外部模型该兜,是我们的卡太薄。**
   ★ 要做的不是「让兜底更顺」,是**把那些问题编码进卡里**。
★★★ 这个比例会随版本下降 —— ★ 而那条下降曲线
   **就是「我们追上到什么程度」的客观记录**。
★★ 所以每一版都要报这个数,★★★ 并和上一版对比。
```

# ★★★ 第八页 · 三条红线（★ 这一页单独放）

```

     ★ 不是「宽松一点」,是**一模一样**。
```
