## 四、🔴 错号 #113：选股池跨容器对不上（新查出来的）

**怎么查出来的**：本容器是新的，池子掩膜（parquet）不在库里 → 必须重建。重建完发现
`流动性池_报告.json` 和库里那份**不一样**：

| | 库里（B 路昨夜） | 本容器重建 |
|---|---|---|
| 低档 成分只数_最少 | 821 | **824** |
| 中档 成分只数_最少 / 中位 | 604 / 913 | **607 / 914** |
| 高档 成分只数_最少 | 337 | **338** |
| 中档 复合年化 / 卡玛（= 技术面主对标） | 7.28% / **0.18** | 7.30% / **0.181** |
| 低档 / 高档 卡玛 | 0.208 / 0.171 | 0.208 / **0.172** |

**排查到哪一步了**（★ 只说查实的）：
- ✅ **不是随机**：同容器连跑两次技-1，12 个版本的卡玛**逐位相同**（`out_二次_1114/`）。
- ✅ **票单子没变**：`烤新池_1106.py` 重烤后，`pool_NEWPOOL_ALL_1106.csv` 和
  `烤新池_报告_1106.json` 跟库里**一个字节没差**（候选 2816 · 入池 2808 · 退市 972 · 每只票的 bar 数全同）。
- ✅ **原始行情没变**：`market_ext_1105/` 的 2,977 个文件**在 git 里**，HEAD 一样 → 原始数据一样。
- ✅ **两个烤面板/建池脚本都是 `sorted()` 遍历**，没有目录序依赖。
- 🔴 **那差在哪**：票单子和 bar 数都一样，但**价量的值**不一样（池子门槛只看价 ≥5 和 ADV20）→
  差在**面板里的数值**上，不在名单上。日净值曲线从**第二天 2015-01-05 就开始分叉**（2765/2766 天都不同，
  起点处相对差 ~1.3e-5，量级对得上「几只票进出」）。
- 🔴 **根因没定**。★ 三个待查的方向，按可疑度：
  ① B 路昨夜的 newpool 面板**可能不是昨夜重烤的那张**（他们重烤的是并池2004 那张，有指纹闸；
     newpool 这张**没有任何指纹检查**）；② 分红/并股系数这两个登记点在两个容器里取到的不是同一份；
     ③ 拆股修正走 engine 的函数，engine 的缓存状态在两个容器里不同。

**代价（要跟着说的）**：
- ★★★ 「主对标 0.18」这个数**在所有技术面报告里被引用**（《192》《133》《140》都用它）→ 它会漂。
- ★★ 本轮三条臂的结论**方向没变**（三条都 > 主对标；后两条 > SPY 0.399；挪一天都掉回 0.399 以下），
  🔴 **但这是运气好** —— 漂 0.039 的量级，足够把一个贴着门槛的判据翻过去（见下）。
- 🔴 **判据真的被翻过一次**：trend_following 第一道，《192》报告 **2/3**、本轮重跑 **3/3**。
  ★ 原因是挪 2 天那版的卡玛差只有 **+0.004**（报告那边是 −0.002）—— **一个 ±0.003 的抖动决定了判据的正负**。
  ★★★ 噪声基线是 **0.0713**，这个 0.004 比它小一个半数量级 → **这一格说「同向」还是「不同向」都不算有信息**。

**立规矩 (76)：池子也要指纹，和面板一样（规矩 70 的姊妹条）。**
★ 任何引用池子出来的数的报告，必须同时写下**池子指纹**：三档的「成分只数 最少/中位/最多」+「调仓次数」+ 主对标卡玛。
★★ 跨容器重跑**先比指纹，指纹不一样就不许比结论数**（否则会把「输入不同」当成「结果不稳」或反过来）。
★★★ 新容器里重建池子后，**指纹和报告里的不一致 → 当场停下来报，不要接着往下跑**。
