# ★★★ 第 1 问 · 首页「先给票」，怎么给才不构成推荐（★ 这一问最要紧）

```
假设你同时是:一家美国注册投资顾问机构的**首席合规官**,
            和一位做过多个零售券商 App 的**首席产品官**。

     ★ 哪怕我一个字的「建议」都不写,一个分数都不给,
       ★★ 用户看到的仍然是「**这个产品今天把这三只摆在了我面前**」。

【请回答五条】

    ★★★ 是靠**措辞**、靠**排序方式**、靠**免责声明**,还是靠**让用户自己选筛子**?

(c) ★★★ **如果「不构成推荐的首页票单」确实可以存在,

(d) ★★ **有没有一种首页,既不给票单、又不是问卷、又不会让用户立刻走?**

# ★★★ 第 2 问 · 技术面 + 基本面「融合」，到底怎么融

```
假设你是华尔街顶级的量化研究主管,带过多因子和多策略的团队。

★ 我手上有两套独立的能力:
   ① **技术面**:完整的分层判定(看多久 / 走得直不直 / 趋势还是震荡 /
      位置与空间 / 最近量价 / 什么算走坏)
   ② **基本面**:估值 · 赚钱能力 · 成长 · 负债 等逐项判定(带公布日,时点安全)

★★ 现在要做第三类,我们内部叫「**融合面**」——
   ★★★ 既用技术面条件、又用基本面条件的做法。

【我现在的做法,★★★ 而我怀疑它过于简单】
  ★ 我只写了一种组合方式:**两边都要成立(AND)** ——
    技术面条件成立 **且** 基本面条件成立 → 才算这套做法的前提成立。

【请回答五条】

(a) ★★★ **业内把技术面和基本面组合起来,一共有哪几种做法?**
    ★ 请列全,并对每一种说明:**它具体怎么执行**。
    ★★ 标 [原文/有出版物] / [通行] / [你的推断]。
    ★★★ 我特别想知道这几种是不是真的存在、以及它们的名字:
       · **先基本面定池子,再技术面定时机**(两段式)
       · **两边都要成立**(AND,我现在的做法)
       · **两边打分加权合成一个总分**
       · **一边做主、另一边只做否决**(veto)

(b) ★★★ **这几种做法选出来的票,差别有多大?**
    ★ 请说明**分歧的机制**(★★ 不是「结果会不同」这种空话,
      ★★★ 而是「**为什么**会不同、差在哪一类票上」)。

(c) ★★★ **原著里本来就是融合的那几套,原著自己是怎么组合的?**
    ★ 具体问:**欧奈尔的 CANSLIM** —— 它的 C/A(盈利增速)和
      L/N(形态、新高)在原著里是**同时要求**,还是**有先后顺序**?
    ★★ 请给**原文那句话**(书名 + 章节 + 原句)。
    ★★★ 如果原著没说清,**请直接说没说清** —— ★ 那我们会保持不装。

(d) ★★ **哪一种组合方式对「某一边数据缺失」最稳?**
    ★★★ 这一条对我很实际:**我们的基本面只覆盖一部分股票** ——
       ★ 在没有基本面数据的票上,融合面这一整类**判不了**。
       ★★ 请问:业内遇到这种情况是**整类跳过**,还是**降级成单边**?
       ★★★ 如果降级,**怎么让用户知道他看到的是降级版**?

(e) ★★★ **最后一问,请诚实回答:**
    ★ 「融合」是不是只是**把两个筛子串起来**?
    ★★ 还是说技术面和基本面之间**真的存在交互作用**
       (即:两边同时成立时的效果,**不等于**两边各自效果的叠加)?
    ★★★ 如果只是串筛子,**请直接说** —— ★ 那我们就不把它当成第三类能力,
       只当成「两个筛子的组合」,**不额外立一个概念**。
```

# ★★★ 第 3 问 · 「他调了 N 次参数」，那个折价该怎么算

```
假设你是华尔街顶级的量化研究主管,熟悉多重检验和过拟合的统计处理。

★ 背景:我们让散户**自己定义筛选规则**,然后帮他**检验**这条规则。
★★ 我们最担心的事(原话):
   「**他会把我们给的检验工具当成背书工具用** —— 不断微调参数,
     直到系统显示『通过』。那叫更高一层的过拟合,**而且他自己不知道。**」

★★★ 所以我们决定在界面上**显示「这是你第 N 次微调」**。

【而这里有一个我拿不准的地方 —— 请直接评判】
  ★ 有一种做法是:在次数旁边显示一个概率,按
      **1 − (1 − 0.05)^N**
    计算「结果由纯运气拼凑出来的概率」(★ N=17 时约 58.2%)。

  ★★★ 我的质疑:**那个公式假设每一次尝试是相互独立的检验** ——
     ★ 但实际上散户的调参**高度相关**:把 20 日均线改成 19 日,
       两次检验用的几乎是同一批数据、同一个信号。
     ★★ 所以我怀疑那个数是**高估**的(可能高估很多)。
     ★★★ 而如果我们在界面上显示一个**错的概率**,
        **那比什么都不显示更糟** —— 因为它看起来很精确。

【请回答五条】

(a) ★★★ **那个公式(独立假设)用在「相关的调参尝试」上,错得有多厉害?**
    ★ 请说明**方向**(高估还是低估)和**量级**。
    ★★ 标 [原文/有出版物] / [通行] / [你的推断]。

(b) ★★★ **处理「相关的多重检验」,正确的做法是什么?**
    ★ 请给**可以直接实现的做法**,并说明每一种:
      ① 它**具体怎么算**(要什么输入)
      ② 它的**已知缺陷**
      ③ [原文] / [通行] / [你的推断]
    ★★ 我知道有 Deflated Sharpe Ratio 这类东西 ——
       ★★★ 请说明它**具体怎么处理尝试之间的相关性**,
          ★ 以及它**需要我们提供什么**(我们手上有每次尝试的完整结果)。

(c) ★★★ **如果要在界面上给用户显示一个数,那个数该是什么?**
    ★ 请给**一个具体的量**和它的**算法**。
    ★★ 而且请明确:★★★ 这个数**会不会被用户误读**?如果会,误读成什么?

(d) ★★ **如果没有一个「能算、而且不会误导」的数** ——
    ★★★ **请直接说没有。**
    ★ 那我们会改成**只显示次数 + 一句文字**,不显示任何概率。
    ★★ 这种情况下,**那句文字该怎么写**?(★ 请给具体措辞)

(e) ★★★ **最后一问,请诚实回答:**
    ★ 显示「你已经调了 17 次」这件事,**会改变散户的行为吗**?
    ★★ 还是说他会**学会无视它**(就像无视所有警告一样)?
    ★★★ 如果是后者,**请直接说** —— ★ 那我们会去想别的办法
       (比如**限制功能**而不是**显示提示**),★★ 而不是做一个让自己心安的提示。
```
