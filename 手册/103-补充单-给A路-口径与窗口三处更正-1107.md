## 二、三处更正

### 更正① ★★★ 收益口径改成「全收益」——**策略侧和基准侧一起改**

```
★ 《99》里一个字都没写收益口径 → 默认跑的是**纯价格**（不算分红）。
★★ 引擎其实 10-29 就支持全收益了,只是默认关着（《24》#76）。

★ 怎么开（引擎零改动,run_one 不收这个参数）:
    import engine.data as data
    data.TOTAL_RETURN_DEFAULT = True          # ★ 跑之前设,并 assert 一下
```

```
⚠ ★★★★★ 最关键的一句:**两侧必须一起改。**
★ B 路实测过（《24》#77）:只给**基准侧**补分红,
   基本面唯一还站着的那条 t 从 2.02 掉到 **1.86** —— 看着像「它死了」。
→ ★★ 两侧都补之后,t = **1.98**。★★★ **它没死。**
★ 原因:策略和基准**持有同样那些天**,两边都少算分红,
   ★★ 只补一边等于**单方面给对手加分**。

★★★ 所以规矩㊽:口径改动（分红 / 摩擦 / 滞后 / 窗口 / 池子）一律**两边同时改**;
   ★ 「只改一边」算出来的数**标成中间数,不许进结论**。
```

### 更正② ★★ 窗口不用砍到 2016 —— **可以拉到 2004**

```
★ 《99》写的是 2016~2025,理由是「考卷那批数据只有 2016 年起」。
→ ★★★ 这个理由**已经不成立**:数据组 11-07 把考卷 1,042 家 2016 年以前的日线交了
   （`exam_pre2016_1107/`,988 家从 2014 或更早,707 家从 2004 起）。
★ 行情三块拼起来,大多数票能到 2004 → ★★ 《96》里那条「窗口必须改到 2016」**作废**。

⚠ ★ 但财报数据**仍然只能从 2009 年起**。
→ ★★★ 所以基本面 23 条的实际可跑窗口是 **2009~2025**,不是 2004。
   ★ 这个限制必须写进报告,不许写成「2004 起」。
```

### 更正③ ★ 池子：3,834 → **3,858**，池表要换 22 年那张

```
★ 《99》写的 3,834 是并池第一版。★★ 后来发现 manifest 只读了一份（《24》#72）,
   两份都读之后是 **3,858 只**。
★★★ 另外:池表（排名表）必须换成 22 年那张,否则 universe 掩膜会把苹果微软**全排除**（#74）:
    面板:probe/并池2004_1107/ohlcv_panel_newpool.parquet
    池表:probe/并池2004_1107/pool_MERGED2004_ALL_1107.csv   ← ★ 52,061 行,2005~2026
★ 可买名单:**全量 3,858 只,一档,不留静态留出池**（Lin 1107 16:58 拍板）。
```

## 三、报告头部必须有这一行（规矩㊼）

```
【本次口径】全收益 · 摩擦档 X · 窗口 2009-01-01~2025-12-31 · 池 并池2004(3858,一档) · 标签滞后 1 天
```

```
★ 五个字段少任何一个,这份报告作废。
★★ 理由:今天一天因为「口径没跟着数走」翻掉的结论有好几条 ——
   ★★★ 口径不是格式要求,它决定数字是什么意思。
```

## 四、内存提醒（★ 会被杀进程的那个坑）

```
★ 机器总共 7 GB,可用约 4 GB。
★★ 22 年 × 3,858 只整块装进去约需 9 GB → ★★★ OOM,exit 137,我中过两次。
→ ★ 解法:把面板**按窗口裁行**之后再放进 cache._PANEL,
   前面多留 **440 个交易日**当预热（给 252 日均线之类留足）。
★★ 不要改 dtype（别转 float32）—— ★★★ 会和之前的结果产生精度漂移,对不上账。
```
