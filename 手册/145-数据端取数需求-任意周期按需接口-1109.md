# 《145》数据端取数需求 · 任意周期按需接口（1109）

> ★ 给数据组。★★ Lin 1109 17:49 定：小时级这一期只做**分析**，不做回测成绩；周期不限于 1h/4h，
> 用户问 30 分钟、15 分钟都要能答。

---

## 零、三秒版

```
★★★★★ 我们要的不是「把全池小时线落盘」，是一个**按需取数的接口**：
   给一个代码 + 一个周期 + 一个区间 → 还回这一段 K 线。
★★ 为什么：分析是用户问哪只、问哪个周期才取哪一段;不是批量跑。
★★★ 所以不要先去囤数据 —— **先把接口通了**，囤不囤以后再说。
```

---

## 一、背景（大白话）

用户在产品里问「NVDA 这会儿 15 分钟线上什么状态」。

技术面大师卡要读这一段 K 线才能答。它**不经过回测引擎** —— 回测引擎现在写死只读日线
（`daily.json`），这一期不动它。所以数据端这边要给的，只是「把这一只、这个周期的 K 线取出来」。

**和回测完全分开**：这一期不出任何小时级的回测成绩、胜率、t 值。那件事要改引擎，是另一期。

---

## 二、要干啥

### ① 一个取数接口（★★★ 这是唯一的必做项）

| 入参 | 说明 |
|---|---|
| 代码 | 单只，如 `NVDA` |
| 周期 | `1min` / `5min` / `15min` / `30min` / `1h` / `2h` / `4h` / `1d` —— ★★ 有哪些给哪些，没有的明确报「没有」 |
| 区间 | 起止时间 |

还回每根 K 线的：**时间戳 · 开 · 高 · 低 · 收 · 成交量**。

### ② 每次还回时必须带的四样（★★★★★ 少一样我们就没法用）

```
1. **时间戳带时区**，并说明是**北京时间还是美东时间** —— ★★ 这条最容易出错
2. **这根 K 线代表的区间是左闭右开还是左开右闭**（★ 09:30 那根是 09:30–09:45 还是 09:15–09:30）
3. **复权口径**：是否已做分红/拆股折算。★★★ 如果做了，用的是哪种
4. **数据时点**：这批数据最后更新到什么时候
```

### ③ 要明确回答的五个问题（★★ 不用先改代码，先告诉我们答案）

```
① 哪些周期**真的有**？最细到几分钟？
② 历史能回到**哪一年**？（★★★ 日线我们有 20 年以上;分钟线通常短得多，这条很关键）
③ **盘前盘后**的成交算不算在里面？能不能分开给？
④ **停牌、半日交易日**（感恩节次日这种）怎么表示？
⑤ 分钟线的**分红/拆股折算**现在做不做？如果不做，我们自己折算需要什么原始字段？
```

## 三、不要做的

```
★★★ 不要先批量落盘全池的分钟线。
★ 原因：按需取数的话一次只要一只，量很小;批量落盘全池 15 分钟线是几十 GB，
   ★★ 现在没有任何一条流程会用到它。
★★★★★ 先把接口通了，拿 3~5 只票验一遍四样口径对不对，再谈规模。
```

## 四、验收（★ 怎么算这件事做完了）

```
拿 **NVDA / AAPL / JPM** 三只，各取 `15min` 和 `1h` 最近 10 个交易日，能做到：
   ✓ 时间戳带时区，且和官方收盘时间对得上
   ✓ 同一天的 15 分钟线合成起来，等于那天的 1 小时线（★★ 自己能对上）
   ✓ 1 小时线合成起来，等于那天的日线的开高低收（★★★ 这条是最硬的自检）
   ✓ 上面四样口径每次都带着
→ ★★ 第三条对不上就说明口径有问题，★★★ 别往下做，先告诉我们。
```

## 附：这件事的边界

```
★★★ 这份需求单**只管取数**。
★★ 「20 日新高在 15 分钟线上算多少根」这个问题**不在这里** ——
   那是方法口径问题，正在另外走（问 Gemini 行业做法，见《146》）。
★★★★★ 数据组不需要替我们决定任何参数换算。
```
