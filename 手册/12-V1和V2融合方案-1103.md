# ★★★ 第 6 条 · 融合带来的新问题（★ 必须写出来，否则会以为融完就好了）

```
★★★ 一 · **同一个数,两套来源,可能不一样。**
   ★ 例:ROIC —— V1 从 `collect_fundamental_snapshot` 拿,
     V2 从回测库的派生算子算(★★ 覆盖 42.8%)。
   ★★★ 两个数**不一致的时候,界面上显示哪一个?**
   → ★★ 我的倾向:**产品展示一律用 V1 那一套**(它是当前值,而用户问的是现在);
     ★★★ **回测一律用 V2 那一套**(它是 PIT)。
     ★ 而**两套的数不许出现在同一行上**。
   → ★★ **这一条要你拍板。**

★★★ 二 · **18 张卡不能直接变成 agent。**
   ★ 它们是**研究框架**,不是可执行策略 ——
     ★★ 没有「进场扳机」「什么情况算走坏」的量化定义。
   ★★★ 所以「帮我盯着巴菲特护城河条件」这种请求**做不了**,
      ★ 而要如实说:「这套方法是一个**研究框架**,它没有一个可以自动盯的触发条件。」

★★★ 三 · **V1 的 `common_rules` 有一条我们没有,要并进来:**
   ★★★ 「**强结论必须可证伪** —— ★ 重要判断同时给出**最强反方**、
      **失效条件**和**下一验证节点**。」
   ★★ 这一条比我们现有的边界更进一步 ——
      ★ 我们有「不许下结论」,★★★ 但没有「**下了结论就必须配反方**」。
   → ★ 我的倾向:**并进共用边界 6.10**(它和「智慧」是同一件事)。

★★★ 四 · **研报流程(`equity-research`)在 V2 里没有位置。**
   ★ V2 的统一输出是**三样**(面向决定);
     ★★ 而研报是**一整份文档**(面向论证)。
   ★★★ 我的倾向:**它是第五条路** ——
      ★ 用户明确要一份研报的时候才走,★★ 而且它的输出**不套三样模板**。
      ★★★ 理由:V1 自己的 description 就写了
         「**仅用于用户明确要求完整正式研报**」—— ★ 那个边界已经划好了。
```
