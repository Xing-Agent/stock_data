# 策略产品规格书 v3

> 版本：v3 · 2026-10-31 · 维护：策略组
> 用途：**一条策略 = 一个产品。所有策略产品用同一张规格表。**
> 升级规则：改了这份就把版本号 +1，并在文末「版本记录」写一行改了什么。

---

## 第 0 节 · 两条总规矩

```
★ 规矩一:**缺栏不许出厂;栏里写「说不清」可以出厂。**
★ 规矩二:三样东西不许出现 ——
   ① 任何对未来的预测
   ② 任何买卖方向建议
   ③ 任何我们自己合成的综合评分
```

**规矩一的意思：** 我们不靠「成绩好不好」挡产品，靠「说清楚了没有」挡产品。
一条成绩平平但每格都如实填满的策略，可以出厂；一条成绩很好但第 9 格空着的，不行。

---

## 第 1 节 · 规格表十二格

| # | 格 | 不许留空 | 说明 |
|---|---|---|---|
| 1 | **这是哪个版本** | ★ 是 | ★★★ **三档 + 用户自己的**，见第 2 节 |
| 2 | **规则逐条的出处** | ★ 是 | ★★★ **五档逐条标**，见第 2 节。**这一格就是「门一·保真度」** |
| 3 | 要什么市场环境 | | 每条标出处等级 |
| 4 | 要什么样的股票 | | 市值 / 流动性 / 波动 / 行业 |
| 5 | **这个条件在十二年里成立了多久 · 哪几年完全不成立** | ★ 是 | 我们自己加的一格，见第 3 节 |
| 6 | 分层表现：牛市 / 熊市 / 横盘 | | |
| 7 | **条件成立时的收益** | | ★ 不是全期平均 |
| 8 | 两条基准线 | | ① 和同环境随机进场比 ② 和同等仓位大盘比 |
| 9 | **代价** | ★ 是 | 最大一次亏多少**美元** · 最长连亏几次 · 最长多久不赚钱 |
| 10 | 明确不适用什么 | | |
| 11 | **这个历史数字结实不结实** | | t 值 / 两段一致性。★ 可以写「样本不够，说不清」 |
| 12 | **样本外** | ★ 是 | ★ 新增，见第 4 节 |

### 第 9 格为什么要用美元而不是百分比

百分比零售端读不出痛感。「最大回撤 18%」和「这一笔亏了 1,800 美元」是两种东西。
**代价这一格必须让人疼一下。**

### 第 11 格为什么可以写「说不清」

因为 `t ≥ 3.0` **不是上线门槛**，它是说明书里的一格。详见《02-测试方法手册》第 1 节。

## 第 2 节 · ★★★ 两个轴，别混（v3 修正）

v2 把「版本」和「出处」混成了一件事。**它们是两个轴：**

```
★★★ 轴一 · **产品版本**(第 1 格)—— 同一条策略的几个版本,用户在界面上选哪一个
★★★ 轴二 · **逐条出处**(第 2 格)—— 这个版本里**每一条规则**各自从哪来
```

★ **一个版本里，不同规则可以有不同出处。** 这是常态，不是例外。

---

### ★★★ 轴一 · 产品版本：三档 + 用户自己的

| 档 | 名字 | 这一档的规则从哪来 | 测过没有 |
|---|---|---|---|
| **①** | **原著版** | 原文 grep 得到的那些 | ★ 我们测 |
| **②** | **行业版** | ★★ 行业/外部模型推荐的做法 | ★★★ **我们测过才算第 ② 档** |
| **③** | **XING 修正版** | 我们回测之后改的 | ★ 我们测 |
| **④** | **用户自己的** | 用户在平台上自己调的 | ★ 他想测我们帮他测 |

#### ★★★ 第 ② 档的准入条件（v3 新增，今天实测逼出来的）

```
★★★ **外部模型推荐 ≠ 第 ② 档。** 必须「我们自己跑过并验证」才算。
★ 跑之前,它只是第 ⑤ 档出处(见轴二),不是一个产品版本。
```

**为什么要加这一条 —— 今天的实测：**

我们向外部模型要了一批「行业最合适」的参数。追问之后它自己承认：

> 「我存在**将大量工程经验参数与个人主观调优值包装在权威来源下**的严重问题」

★★ 它给的全部数字里，**拿得出确切原句的只有 2 条**（O'Neil 的 7~8% 止损、
Paul Tudor Jones 的 200 日线），★★★ **其余全部改标「我自己估的」**。
★ 而且它自己说：「你们的代码必须**针对自己的股票池重新进行参数敏感性回测**」。

**所以第 ② 档如果不设这个准入条件，它就会变成「外部模型猜的」顶着「行业最好的」的名字出厂。**

★★ 已有的样板：`engine/configs/vcp_momentum.yaml`（流派二 · 龙头动量）——
★ 它跑过，而且配置头部自己写着「我们搜的 = 0 条」，★★★ 这是第 ② 档该长的样子。

---

### ★★★ 轴二 · 逐条出处：五档

```
① 原著                        —— 原文 grep 得到
② 行业改进                    —— 行业通行,★ 且我们做过验证
③ XING 修正版                 —— 我们改的
④ 用户自己的                  —— 用户自己调的
⑤ 外部模型回答·未经我们测试   —— ★ 外部模型给的默认落点
```

★★★ **第 ⑤ 档是外部模型的默认落点。** 要往上爬只有两条路：
```
★ 在方法卡原文里 grep 得到  → 爬到 ①
★★ 我们自己跑出来并验证     → 爬到 ②
★★★ **它自己说自己是原文,不算。**
```
★ 落地的检查是第三道卡口 `engine/checks/source_grep_audit.py`：
**不查「出处填了没」，查「这个数在方法卡原文里 grep 得到吗」。**

---

### ★ 第 ③ 档只许装两类改动

```
✅ 修实现错误       —— 我们写错了,改对
✅ 补缺失机制       —— 原著有、我们没实现。★ 必须全矩阵同步装,严禁选择性补
❌ 为了让成绩变好而调参数      ← 100% 过拟合,没有辩解空间
❌ 换基准 / 换样本区间         ← 重大违规
```

★★★ **把外部模型估的数写进代码，属于第 ③ 类「调参数」，不属于第 ② 类「补机制」** ——
★ 因为「补机制」补的是**原著有而我们没实现**的东西，★★ 而一个外部模型的估值，原著里没有。

---

### ★ 原著版不许用我们填的东西凑完整

原著没规定的地方，原著版那一档就写「原著没规定」。
**不许拿我们的默认值填进去，然后整档标成「原著」。**

## 第 3 节 · 第 5 格（条件成立了多久）—— 这一格是我们自己加的

**理由：** 一条策略写着「要指数在 200 日均线上方才开仓」，听起来很合理。
但如果这个条件在十二年里只成立过 8% 的时间，那它实际上是一条**几乎不开仓的策略** ——
而第 7 格的「条件成立时的收益」会很好看，因为样本极少。

**实测的真例：** 有一条链三道闸的交集只剩**每天 0.17 只**可选，而槽位有 8 个 →
它跑完全程只成交 **1 笔**。另一条 **0 笔**。
如果没有第 5 格，用户看到的会是「暂无数据」，而不是「这条策略几乎不开仓」。

**所以第 5 格和第 7 格必须同屏。** 单看第 7 格会骗人。

---

## 第 4 节 · 第 12 格（样本外）—— ★ 新增，两行

```
第一行:「**本策略未经历史样本外验证。**」
第二行:「**自 2026-10-31 起进入纸面模拟,实时样本外成绩累积中。**」
```

### 为什么第一行必须这么写

实测：我们**没有任何干净的留出池**。

```
时间维度:2022–25 已经反复看过          → 污染
股票维度:0 只候选是没碰过的,落到 20% 哈希切分后
         ★ 49/49 = 100% 都已经跑过      → 污染
```

**这不是可以含糊过去的一格。** 写「已通过样本外检验」是假话；
留空违反「缺栏不许出厂」。所以如实写第一行。

### 第二行是唯一的出路

```
过去的数据我们都看过了,但未来的数据我们还没看过。
→ ★ 从冻结日起的行情,是我们唯一一份真正样本外的数据。
```

**第二行会随时间变得越来越有分量**，而且它是我们唯一能给用户的「不是回测」的数字。
下一批策略**一开始就锁死最后两年**，不要再重复这个错。

## 第 5 节 · 两层（不是三层）

```
咨询层  —— 大师。同样的问题,不同用户给的条件不一样,输出也不一样
策略层  —— 会自己往下跑的东西
            ★ 融合是策略的一种(复杂策略),不是单独一层
```

### 边界：**这个输出会不会自己往下跑**

```
会自己往下跑  → 策略层
不会          → 咨询层
```

**物理位置：用户按下「保存」把它变成自己的 agent 那一下。**
保存之前 = 咨询（不给具体点位）；保存之后 = 策略（给）。

### 为什么融合不是单独一层

因为它**同样的输入会给同样的输出** —— 这正是策略层的判别准则。
融合只是规则更多的策略，不是另一类东西。

---

## 第 6 节 · 两个大师入口（先做 2 个）

```
① 技术面大师    ← 突破 / 震荡 / swing 全部归这一个
② 基本面大师
★ 融合大师先放一放
```

**主体是我们自己可编码的。** Gemini 只兜那 20% 我们覆盖不了的，**且必须标第 ⑤ 档**。

**咨询层是 skill → 策略组做。**

---

## 第 7 节 · ★ 大师现场给出的策略（未测）—— v2 新增

用户问大师「我想做突破该怎么做」，大师会给出一套做法。**那套做法没有经过我们的测试。**

### 这不是问题，只要说清楚

```
★★★ 对用户的原话:「**这套做法我们还没有测过。**」
★ 如果用户想测 → ★★ 我们帮他测。
★ 用户不想测、直接拿去用 → ★★★ 可以。那是他的选择。
```

**所以规格表在这种情况下这么填：**

| 格 | 怎么填 |
|---|---|
| 1 这是哪一档 | **⑤ 外部模型回答·未经我们测试**，或 **④ 用户自己的** |
| 2 规则逐条的出处 | 大师给的部分标第 ⑤ 档，用户改的部分标第 ④ 档 |
| 5 · 7 · 9 · 11 | ★★ 全部写「**未测试，无数据**」 |
| 12 样本外 | 「未测试」 |

★ 这完全符合「**缺栏不许出厂；栏里写「说不清」可以出厂**」—— **「未测试」就是一种「说不清」。**

### ★★★ 用户把它变成自己的 agent 之后，怎么测、怎么上、怎么用，是他的事

```
★ 保存那一下之后,它就是用户自己的策略了。
★★ 我们提供回测工具、提供推荐的默认做法,★★★ 但他要改要调,那是他的选项。
```

---

## 第 8 节 · ★★★ 底线（v2 新增）—— 用户自己的策略，我们唯一还管的几件事

用户的策略我们不替他判断好坏，但这几条不让过：

```
★★★ 一 · 不许出现我们没有的数据
     用户的策略里要是引用了分钟级、盘口、期权链、新闻文本 —— ★ 我们没有,直接拦,
     不许用近似值悄悄替代。

★★★ 二 · 不许出现未来函数
     任何「当天收盘才知道、却拿来当当天开盘的进场条件」的东西,★ 直接拦。
     ★★ 这一条不是口味问题,是对不对的问题。

★★★ 三 · 笔数 < 30 不给任何统计结论
     ★ 可以给他看流水,★★ 但不给 t 值、不给胜率、不给「这策略好/不好」的话。

★★★ 四 · 不许我们替他做预测、给方向、给综合评分
     ★ 这三样在任何档位下都不出现 —— 第 0 节规矩二。

★★★ 五 · 他的策略成绩不许被我们拿去对外宣传
     ★ 那是他的东西,不是我们的业绩。
```

### 为什么底线只有这五条，而不是更多

```
★ 前两条是**对错问题** —— 数据没有就是没有,未来函数就是错的。这两条没得商量。
★★ 第三条是**我们自己的门二**,对所有档位一视同仁。
★★ 第四、五条是**我们自己的本分** —— 管的是我们说什么话,不是管他怎么做。
★★★ 除了这五条,**他想怎么调就怎么调。** 调得好不好是他的判断,不是我们的。
```

---

## 第 9 节 · 对外说话

```
❌ 「这些方法已经失效」
✅ 「这些方法在我们的实现上没有通过检验」
```

**凡对外说某方法「失效」，必须先过门一（保真度）。**
实测乙类不一致 55 处，其中 7 条疑似是我们自己的实现错误 —— 那 7 条说「失效」说的是我们自己。

**Gemini 给的法规引用一律不能直接对外**（已核出注水）。法规的事走律师。
