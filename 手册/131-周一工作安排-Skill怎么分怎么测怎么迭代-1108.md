## 三、谁改什么（★ 一句话规矩，细表见《130》）

```
★★★★★ **改完之后，同样的问题问系统，它会不会给出不一样的答案？**
   · 会  → **问 Lin**
   · 不会 → **自己改**

★ 「不一样」只看三件：① 选出的**股票**变没变 ② **买/卖/继续拿**的结论变没变
   ③ 原来**能通过**的会不会变成通不过。
★★ 三个都不会 = 表达问题，自己改。★★★ 拿不准 → 当成要问。
```

| 自己改 | 必须问 Lin |
|---|---|
| 话术、示例、解释、提问顺序、表格改列表、K 线怎么显示、错别字 | ★★★ 任何**数字门槛** · 加/删**筛选条件** · **买卖规则** · **排序方式** · **持仓只数** |
| | ★★ 「可能」改成「大概率」这类**对外口径** · 任何写**成绩/收益/胜率**的话 |
| | ★★★★★ 动 **共用边界** |

```
★★ **问的方式**：每组维护一张「要问 Lin 的清单」，★★★ **攒着，每轮固定一次**
  （建议周二）一次性过完 —— ★ 不要零碎打扰，★★ 他还要做策略研究，那部分没人能替。
```

## 四、测什么（★ 四类，前两类机器做）

| 类 | 测什么 | 谁 | 多久 |
|---|---|---|---|
| ★ **一 · 跑得通吗** | 38 张各给 3~5 个标准问题；★★ 有没有把内部标记/测试记录/开发讨论**漏给用户** | 机器 | 几分钟 |
| ★★★ **二 · 边界守住了吗** | 逐条对照共用边界；「不许说的话」逐条验；★★★★★ **有没有人改了判据却没走 Lin** | 机器 | 半小时 |
| ★★★ **三 · 没想到的情况** | ★ 让 AI 针对每张造 **20 个刁钻但合理**的输入：超范围、中途改主意、问别的市场、信息残缺、自相矛盾 | 机器造题 + 人看 | 半天 |
| ★★ **四 · 看得懂吗 / 好不好用** | ★ AI 扮用户把流程走一遍，标「哪一步会懵、哪句看不懂、想问但没被问」；人只看标出来的点 | AI + 人 | 半天 |

```
★★★★★ **第四类（体验）必须在冻结之前做完。**
★ 原因：体验评估会**改流程**，而一二三类测的就是流程 ——
  ★★★ 放在测试之后，它一说「顺序该换」，刚测完那一轮**全部作废**。
★★ 发版之后的真实使用反馈，叫**事后体验**，★★★ 它喂给**下一轮**，不回头改这一版。
```

## 五、三天一轮怎么走

```
第 1 天  ★★ 事前体验（AI 扮用户走一遍）→ 定流程 · 各组并行改自己那几张
第 2 天  ★ 上午继续改 → ★★★★★ **下午冻结**
         ★★ 冻结顺序**从上游到下游**：共用边界 → 两张大卡 → 小卡 → 前后端接线
         ★ 冻结后机器跑：一类冒烟 + 二类边界 + 三类刁钻输入
第 3 天  ★ 上午**分流修**：A 类文字层当场闭环 / B 类代码层进开发队列
         ★★ 下午**只复测修过的那几张** → 发版
→ ★★ 下一轮第 1 天，顺便看上一版的真实使用反馈
```

| 修复分两类 | 谁 | 多久 | ★ 什么时候复验 |
|---|---|---|---|
| ★★ **A · 文字层**：话术、示例、边界提示、格式 | 运营/产品 | 分钟级 | ★★★ 当场改当场验 |
| ★★★ **B · 代码层**：前端呈现、后端接口、字段、路由 | 技术 | 小时~天级 | ★★★★★ **进队列，下一轮验** |

```
★★★ 三条硬的：
① ★★ **冻结之后进来的优化，一律排下一轮** —— 不然永远「上一轮没测完，新版又出来了」。
② ★★★★★ **一轮新发现 < 3 条 → 结束，发版。**（★ 对应边际效应：第 1 轮最多，之后急降）
③ ★★ **B 类修不完不要硬等** —— ★ 这一版照发，★★★ 但版本说明里**写明哪几条已知、下一版修**。
```

```
★ 另外两条防返工的：
· ★★ **同一轮内，一个 skill 只许一个人写**（否则问题归因不了、容易互相覆盖）
· ★★★ **测试对冻结快照测**（版本号 + md5），★ 修复落下一版，**不边测边改**
```

## 六、这一版（V2.4.x）要做的两件

```
★★★ ① **两张大卡不拆**，只把**日期出处**抽进 `references/出处与沿革.md`。
   ★ 说明：先前判断「大卡里两三成是设计讨论」是**错的** ——
     ★★ 重数后实际各约 **20~25 行（约 3%）**。★★★ 硬拆会切断互相引用的章节，
     那是**制造**耦合，不是减少。
★★ ② **每张 skill 配一组固定题（5~10 道）**：改完只跑它自己那组。
   ★ AI 出初版，各组确认。★★ 一次性成本约一天，★★★ 之后每轮都省
     —— 这才是把「全量重测」变成「只测一张」的那把钥匙。
```

## 七、附：两条引擎缺口（★ 不在这一轮，但要排期）

```
★★★ ① **日内（30 分钟 / 1 小时 / 4 小时）** —— ★ 技术面大师要用。
   · 数据量不是问题：**4 小时全池 22 年约 0.5 GB**（★★ 和现在的日线面板差不多大）；
     ★★★ 1 分钟全池是 **89 GB** → **不要原始分钟线，要数据端预聚合好 30m/1h/4h**
   · ★★★★★ 真正的坎是**回测引擎**：「一天一撮合」是**结构**不是参数；
     喂它四小时 bar 只会得到「把日线换个标签」的**假四小时**
   · ★ 归属：**回测引擎在我们自己仓库，由 Claude 改 + Lin 拍板**
     （★★ 改它会让之前所有回测成绩的可比性中断，所以要拍板）；
     ★★★ 技术组接的是**后一段**：日内数据进产品、测试网、前端展示
   · ★★ 下一步：**先做小试点**（1 条策略 × 50 只票 × 4 小时 × 3 年）把会断的地方撞出来，
     ★★★ 再给工期 —— ★ 现在报任何工期都是猜

★★ ② **定期调仓 + 权重** —— ★ 轮动策略的地基，现在引擎不支持 → 轮动一条都没落地。
```
