# Gemini 使用协议 v1

> 版本：v1 · 2026-10-31 · 维护：策略组
> 用途：**任何一条新策略进来，都按这份跟 Gemini 聊。** 运营可以直接照着用，不需要懂统计。
> 升级规则：改了这份就把版本号 +1，并在文末「版本记录」写一行改了什么。

---

## 第 0 节 · 为什么要有这份（三条今天实测的翻车）

我们不是不信 Gemini。**它在投资知识上确实比我们见过的大多数团队都厚。** 但它有三个
**反复出现、而且不会自己承认**的毛病，这三条全是我们实测撞出来的，不是担心：

| # | 毛病 | 实测证据 |
|---|---|---|
| 1 | **出处注水** —— 把它自己的推断标成【法规原文】 | 我们已经当面点名过一次，它下一轮**照样**把推断标成【法规原文】 |
| 2 | **编数据** —— 凭空说出我们没有的数据粒度 | 它说我们用的是「每分钟级别真实数据」。**我们全库是日线。** |
| 3 | **自相矛盾且不自知** —— 同一份回答里两个标准打架 | 正文写 `t ≥ 3.0`，同一份的矩阵里写 `Z ≥ 1.96`。两个差一倍多 |

还有一条更隐蔽的：**它会顺着我们的话走。** 我们点名说「不要给方向性建议」，它夸了我们一句
不给方向，然后在下一段给了三个方向建议。

**所以这份协议的全部作用就一句话：**

> ### 让 Gemini 的知识进得来，让 Gemini 的出处和数字进不来。
> 它说的**逻辑和做法**我们大量采纳；它说的**出处、数字、法规引用**，一律当成未经核实。

## 第 1 节 · 一条策略进来，标准四轮

**为什么分四轮而不是一次问完：** 一次给它太多，它会挑好答的答、难答的含糊过去，而且
**它会看到我们的结果然后顺着结果说话**。分轮是为了让它在看不到我们成绩的情况下先把话说死。

```
第 1 轮 · 要原文           ← 它说方法是什么。★ 这一轮绝对不给我们的任何回测结果
第 2 轮 · 要使用条件       ← 这方法什么时候适用、什么时候不适用
第 3 轮 · 盲审我们的实现   ← 给它我们的实现,不给成绩,问「这是不是它说的那个方法」
第 4 轮 · 看成绩后的解释   ← ★ 这一轮才给成绩。而且它这一轮说的话,级别最低
```

### 关键纪律：**前三轮一个数字都不给它。**

这叫**盲审**。我们今天做过一次（54 条使用条件盲审翻译），效果是：它在看不到成绩的情况下
判出 **54 条里只有 15 条是真的环境条件，39 条根本不该当开仓门槛**。
如果先给它成绩，它会去解释成绩，而不是判方法。

## 第 2 节 · 四轮的粘贴模板（填空就能用）

> 下面四段可以直接复制给 Gemini。`【】` 里的是要填的。
> **每一轮开头那段「回答规则」必须带上**，不能省 —— 省了它就会注水。

---

### 第 1 轮 · 要原文

```
我在复现一个交易方法：【方法名 / 作者 / 书名或论文】。

请按下面的规则回答。

【回答规则】
1. 每一条判据后面必须标一个出处档位,只能选这五个之一:
   [原文] —— 这句话在原著里有,能逐字找到
   [通行] —— 原著没写,但行业里普遍这么做
   [你的推断] —— 你自己补的
   [不确定]
   [原著明确不这么做]
2. 标 [原文] 的,必须附上原文那句话,以及它在哪一章/哪一节。
   ★ 如果你拿不出原文那句话,就不许标 [原文],改标 [你的推断]。
3. 不许给我任何数字范围是你估的。估的就标 [你的推断]。
4. 如果某一部分原著根本没规定,直接说「原著没规定」。
   ★ 不要替它补一个看起来合理的值。

【我要你交出的东西】
A. 进场判据 —— 完整的、可以写成代码的条件
B. 离场判据 —— 止损、止盈、移动止损,分开说
C. 仓位 —— 每笔多少、总共最多多少
D. 选股池 —— 这个方法本来是用在什么票上的
E. ★ 这个方法的「不做什么」—— 原著明确排除的情况

每一条都要有出处档位。
```

### 第 2 轮 · 要使用条件

```
继续上面那个方法。现在我要问它的使用条件。

【回答规则】
同上,五档出处照旧。另外加三条:

1. ★ 不许用这个方法自己的零件来定义它的大环境。
   例:不许说「当这个方法信号变多的时候就是适用环境」。
   大环境必须用方法之外的东西定义(指数、VIX、市场广度、利率...)。
2. 每一条使用条件必须能用「当天能拿到的数据」算出来。
   不许出现要等事后才知道的东西。
3. 如果一个条件你只能描述成「市场情绪好的时候」这种说不清的,
   ★ 就明确写「说不清,无法量化」。不要硬编一个阈值。

【我要你交出的东西】
A. 什么市场环境下这个方法好用 —— 每条给一个可计算的判据
B. 什么市场环境下不好用
C. 什么样的股票适合 —— 市值、流动性、波动、行业
D. 什么样的股票不适合
E. ★ 时间尺度:这个方法本来是做几天到几周的,还是几个月的
```

### 第 3 轮 · 盲审我们的实现（★ 最重要的一轮）

```
下面是我的实现。★ 我不告诉你它的回测结果,请不要猜、也不要问。

【我的实现】
【把配置原样贴上来 —— 进场/离场/仓位/选股池/参数,一个不漏】

【我能算的算子清单】
【把我们现有的算子列出来,让它知道边界】

【我有的数据边界】
【日线 / 起止年份 / 有没有 VIX / 有没有市场广度 / 有没有财务数据】

【回答规则】
对我实现里的每一条,只判一件事:

  (甲) 和你说的那个方法一致
  (乙) 不一致 —— 并且说清是「比原著松」还是「比原著严」,
       ★ 如果既不是松也不是严、而是方向都变了,单独标出来
  (丙) 原著根本没规定这一条,是我自己填的
  (丁) ★ 这一条不成立 —— 看起来像实现错误

★ 判「乙」的时候,必须引用原著那句话。引不出来就只能判「丙」。
★ 不许顺带建议我改参数。这一轮只判一致性。
```

### 第 4 轮 · 看成绩后的解释

```
现在给你成绩。【贴成绩】

【回答规则】
★ 这一轮你说的所有话,我们都会标成「外部模型回答·未经我们测试」,
  不会直接进产品说明书。所以请不要迁就这个成绩去编解释。

【我要你交出的东西】
A. 这个成绩和你的预期差多少
B. 如果差很多,你认为最可能的三个原因,按可能性排序
C. ★ 每个原因,给我一个「怎么验证它」的具体做法 ——
   要能用我上面列的算子和数据跑出来的
D. ★ 哪些差异是你认为「测不出来」的,直接说测不出来
```

## 第 3 节 · 回来之后的四道验证（★ 这一节不能省）

Gemini 答完不等于可以用。**每一条进我们系统之前过这四道。**

| 道 | 查什么 | 怎么查 | 不过关怎么办 |
|---|---|---|---|
| **一** | 它标 [原文] 的，原文里真有吗 | **在方法卡原文里 grep 那句话 / 那个数** | 找不到 → **强制降成「我们填的」** |
| **二** | 它给的判据，我们算得出吗 | 对着算子清单逐条点 | 算不出 → 记成「缺算子」，不许含糊过去 |
| **三** | 同一份回答里有没有自相矛盾 | 把所有阈值/标准抄成一张表，看打不打架 | 打架 → **原文转录两处，回去追问它自己选一个** |
| **四** | 它的数字是不是编的 | 凡提到「数据粒度/样本量/某公司某产品」→ 追问「**具体哪家公司、哪个产品、哪一年**」 | 答不出具体 → 整条作废 |

### 第一道是今天新加的，而且是四道里最硬的一道

我们原来的检查工具只查「出处这一栏填了没有」。实测它的自测里写着：
source 写「原著(编的)」、写「x」、写「随便写点什么」—— **全部通过检查**。

**所以第一道不查「填了没」，查「这个数在原文里 grep 得到吗」。** grep 不到的，
不管它写的是谁，一律标「我们填的」。

## 第 4 节 · 出处五档（★ 对外说话只认这五档）

```
① 原著              —— 原文 grep 得到
② 行业改进          —— 原著没有,行业通行,★ 且我们做过简单验证
③ XING 修正版       —— 我们改的。★ 只许装两类改动,见下
④ 用户自己的        —— 用户在平台上自己调的
⑤ 外部模型回答·未经我们测试   ← ★ Gemini 说的,默认落这一档
```

**第 ⑤ 档是 Gemini 的默认落点。** 它要想往上爬，只能靠第 3 节第一道（原文 grep 得到 → 爬到 ①）
或者我们自己跑出来（→ 爬到 ②）。**它自己说自己是原文，不算。**

### 第 ③ 档只许装两类改动

```
✅ 修实现错误        —— 我们写错了,改对
✅ 补缺失机制        —— 原著有、我们没实现。★ 必须全矩阵同步装,严禁只给某几条装
❌ 为了让成绩变好而调参数       ← 100% 过拟合,没有辩解空间
❌ 换基准 / 换样本区间          ← 重大违规
```

---

## 第 5 节 · 整轮作废的三种情况

遇到这三种，**那一轮的全部内容都不要，重新问**。不要只挑出问题那条：

1. **它看到了我们的成绩却在前三轮**（我们自己漏贴了）→ 这一轮已污染，重开
2. **第 3 节第四道追问「哪家公司哪个产品」答不出具体** → 它在编，这一轮整体不可信
3. **同一份回答里的核心标准自相矛盾，且追问后它两边都想要** → 它没有真结论

---

## 第 6 节 · 对外说话的红线

```
❌ 「这 151 种方法**已经失效**」
✅ 「这 151 种方法**在我们的实现上没有通过检验**」
```

**凡是对外说某个方法「失效」，必须先过保真度检查** —— 否则我们说的是自己写错了，
不是人家的方法不行。今天实测：乙类不一致 **55 处**，其中 **7 条疑似是我们的实现错误**。

**Gemini 给的法规引用一律不能直接对外。** 已核出注水。法规的事走律师。

---

## 第 7 节 · 一张纸的操作清单（给运营）

```
□ 1. 第 1 轮粘贴模板 → 要原文           ★ 不给成绩
□ 2. 第 2 轮粘贴模板 → 要使用条件       ★ 不给成绩
□ 3. 第 3 轮粘贴模板 → 盲审我们的实现   ★ 不给成绩
□ 4. 回来的四道验证:
     □ 它标[原文]的,去原文 grep —— grep 不到的全降成「我们填的」
     □ 它给的判据,对着算子清单点 —— 算不出的记「缺算子」
     □ 所有阈值抄一张表,看打不打架 —— 打架的原文转录回去追问
     □ 凡提数据/样本/某公司某产品 —— 追问「哪家、哪个、哪一年」
□ 5. 第 4 轮 → 给成绩,要解释           ★ 这一轮的话全落第 ⑤ 档
□ 6. 回来的内容按五档归位,写进那条策略的规格表
□ 7. ★ 原文转录,不要转述。它说错了也照抄,我们在旁边标矛盾
```

**第 7 条单独强调：回来的内容原文转录。** 不要替它改通顺 —— 它自相矛盾的地方
正是我们要抓的，转述一遍就抹平了。
