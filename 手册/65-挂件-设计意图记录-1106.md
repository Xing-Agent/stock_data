## ★★★ 三秒版

```
★★★ **主装备 + 挂件。**
   · **主装备** = 一条原著策略(进场逻辑)
   · **挂件**   = 交易管理:怎么止损、要不要跳过这一单、什么时候提前离场

★ Lin 的依据:**他自己实操、以及他见过的做法都是这样** ——
   ★★ 基金不会一条策略从头执行到尾,会按环境调整。
   ★★★ 他的原话:「这个事情是百分之百可以的。」

★★ 最终形态:**默认替用户配好** —— 用户拿到的主策略,挂件已经装上。
   ★ Lin 原话:「有经验交易员都会把这些配件用得很好,
     但是我们可能到时候就自动给它配上」。

★★★ **但主装备不一定是原著版** —— ★ 可能已经是我们改过的(Lin 10:28)。
★★★ **主策略光着测,组合另外测** —— ★ Lin 10:30:「你不可能测主策略的时候
   把这些小工具都挂上吧?」
★★★ **挂件自己也要有说明书**(七格,见二之二)—— ★ Lin 10:33。
```

# ★★★ 二 · 两条现在就该定下来的（★ 我提的，Lin 还没拍板）

## ★★★ 1 · 挂件只许是「条件清单 + 与/或」，**不许留打分接口**

```
★ 「几个条件**同时满足** → 执行」是**与**关系:没有权重、没有分数 ——
   ★★ **不撞红线。**
★★★ 撞红线的是:「给每个条件配权重 → 加出一个分 → 分数够了就做」。
   ★ 我们那条红线原文:「❌ 打分加权合成 —— 那就是「我们合成的分数」,直接撞红线」。

★★ 这两个在界面上看起来很像,★★★ 但一个能出厂、一个不能。
→ ★★★ 所以挂件的数据结构从第一天就定成**条件清单 + 与/或关系**,
     **不要留 weight 这个字段** —— ★ 留了,以后一定会有人往里填。
```

### ★★★ 防过拟合靠哪一条（★ 修正后）

```
★★ Lin 10:30 指出我混了两件事,他说得对:
   「你不可能测主策略的时候把这些小工具都挂上吧?」
   → ★ 主策略光着测,组合另外测 —— **测法本身是干净的**。

★★★ 但风险不在**怎么测**,在**怎么挑**:
   ★ 10 个工具 × 11 条策略 = **110 个组合**。
   ★★ 跑完挑最好看的几格上线 → 按 5% 误判率,110 格里约 **5~6 格**
      本来没用、只是运气好。
→ ★★★ **解法:报全矩阵,不只报赢的那几格。**
   ★ 每一格都有数(含变差的),「这个工具该挂哪儿」由看表的人判断,
     ★★ 而不是我们先挑好再给 —— **挑选这一步必须是公开的**。
★ 这条也接上 Lin 10:28 那句「不能一刀切」:
  ★★ 全矩阵本来就会显示同一个工具在不同策略上效果不一样。
```

# ★★★ 二之二 · 挂件说明书 —— ★ 七格（Lin 10:33 要求）

```
★★ Lin 原话:「**我们把挂件的这个也像说明书一样,给它做好,
   包括跟主策略之间的组合做好。**」

★ 挂件不用照搬主策略那 12 格(很多格对挂件没意义)。★★ 我提议 **7 格**:
```

| # | 格 | 说明 |
|---|---|---|
| 1 | **这个工具干什么** | 一句话 |
| 2 | **规则逐条出处** | ★ 五档照旧（①原著 / ②行业 / ③XING …） |
| 3 | **挂在哪些策略上测过** | ★ 测过哪些就写哪些，没测的不许推测 |
| 4 | **全矩阵** | ★★★ 每格三个数：**毛利 / 摩擦 / 笔数**。★ 含变差的格子 |
| 5 | **什么时候它不灵** | ★★ Lin：「它之所以叫小工具，是因为它可能在一些时候也不行」 |
| 6 | **代价** | ★ 装上之后「最难受的时候」变成什么样 |
| 7 | ★★★ **什么时候该撤掉它** | ★★ Lin：「有些工具用起来越来越低，那我们就撤掉」 |

```
★★★ 第 7 格为什么重要:★ 它是**「小工具」和「我们发明的指标」的分界线** ——
   **有退役条件的才是工具。**
★★ 别人不会写这一格(写了等于承认自己的东西会过期),★ 而我们写,
   ★★★ 这和「如实写业内没有公认做法」是同一类做法。
```

# ★★ 二之三 · 工具会进会出（★ Lin 10:33）

```
★ 「根据行情的变化,可能会有些新的小工具出来,那再逐渐往里挂」
★ 「之后有些工具用起来越来越低,那我们就撤掉」
→ ★★★ 所以挂件库是**有生命周期的**,不是一次性定稿:
     **进** = 新工具按七格填完才进 · **出** = 第 7 格的退役条件触发就撤
★★ 工程上的含意:挂件要做成**可增删的独立单元**,不能写进主策略的配置里。

★★ 另外 Lin 10:33 提到:「这个工具的使用和怎么使用,行业里面都会有比较明确和
   标准的做法,很多基金都有」→ ★★★ 所以每个工具的第 2 格,
   ★ 先按老规矩问 Gemini 要行业通行做法 + 出处 + 有没有独立实证。
```

# ★★ 三 · 三条工程事实（★ 做之前要知道的）

```
★★★ ① **挂件最容易出的事是「看起来提高了,其实是运气」。**
   ★ 11 条策略 × 10 个挂件 × 3 个参数 = **330 个组合**。
     ★★ 纯靠运气,里面就会冒出十几个「效果显著」的。
   → ★★★ 所以挂件必须**跑前预先登记**:先写死试哪几个、判据是什么、
       **分辨力多少**(规矩⑥),再跑。★ 不许跑完挑好看的。

★★★ ② **每个挂件都要同时报三个数,不许只报收益。**
   ★ 毛利变化 · **摩擦变化** · **笔数变化**。
   ★★ 理由:每多一个条件就少一些交易。少交易可能好(省摩擦 —— 我们有 7 条
     摩擦大于毛利),也可能坏(笔数不够,统计上说不清)。

★★★ ③ **「小周期看形态定止损」要改撮合层,是另一个量级。**
   ★ 日内数据我们**有**(Lin 机器上 2016 起;仓库 `pilot_300/intraday_levels.csv.gz`
     250 只 · 62.6 万行)。
   ★★★ 但 **engine 一天只撮合一次** → 这一类挂件不能和日线挂件排在一起做。
   ★ 其余挂件(移动止损、条件跳过、按大盘强弱提前离场)**只要日线,现在就能做**。
```

# ★ 四 · 「右尾配装单」—— ★★ 我要先跑的那一个量

```
★ 原来我提这个量是想判断「提前止盈有没有用」。
★★ Lin 10:24 说这件他有实操依据 → ★★★ **所以这个量改定位:
   不是否决票,是配装单。**

★ 要算的:**每条策略的收益,有多少来自最大的那 5% 笔交易。**
   · 一条策略 80% 的钱来自前 5% → ★★★ 它该装「**让赢单跑得更久**」的挂件,
     ★ **不能装提前止盈**(砍右尾 = 砍掉收益来源本身)
   · 收益分布平均的 → ★★ 提前止盈就划算

★★ 这是**配装单**:哪个挂件装在哪条策略上。★ 不是「挂件行不行」。
```
