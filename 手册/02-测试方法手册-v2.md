# 测试方法手册 v2

> 版本：v2 · 2026-10-31 · 维护：策略组
> 用途：**一条策略怎么算「测过了」。** 任何人要检查我们的结论，照这份就能复查。
> 升级规则：改了这份就把版本号 +1，并在文末「版本记录」写一行改了什么。

---

## 第 0 节 · 一句话

> **我们测的不是「这条策略能不能赚钱」，测的是「按它自己说的做法做出来，结果和它自己描述的一致吗」。**

未来收益率没有人能保证。我们能给的只有：**历史上、在什么条件下、相对什么基准、表现是什么。**

## 第 1 节 · 两道门（★ 唯一能挡上线的只有这两道）

```
门一 · 保真度    —— 我们的实现确实是那个方法(规格表第 2 格)
门二 · 笔数 ≥30  —— 少于 30 笔不给任何统计结论
```

**除了这两道，任何数字都不挡上线。**

### t 值不进门，进说明书

`t ≥ 3.0` **不是上线门槛**，它是说明书里的一格。一条 t 值不高的策略照样可以出厂，
只要说明书里把这一格如实写出来。

**为什么 t 值不能当门：** 实测，如果要求「四格（原著版/行业版/修正版/对照）全部为正」，
会误杀一半好策略 ——

```
一条真实 t = 2.0 的策略:
  单格 t = 2.0 / √4 = 1.0
  单格为正的概率 Φ(1.0) = 0.8413
  四格全正 = 0.8413⁴ = 0.5011     ← ★ 一半好策略被挡在门外
t = 1.65 时:  0.4001
```

### t ≥ 3.0 是松的，不是极端的

对账 Bonferroni 多重检验校正。★★★ **先说口径，因为这里我们自己犯过一次错：**

```
★★★ 单侧和双侧是两套数,★ 必须说清用哪一套 ——
   我们 10-31 之前报过 3.205 / 3.224 / 3.419,★★ 那三个是**单侧**,当时没标。
★★★ 本手册一律用**双侧**(alpha = 0.05,更常用的口径),单侧的数并列给出备查。
```

| 独立测试条数 M | ★★★ 双侧 t | 单侧 t |
|---|---|---|
| **32** | **3.163** | 2.955 |
| 74 | 3.399 | 3.205 |
| 79 | 3.417 | 3.224 |
| **113** | **3.513** | 3.325 |
| 159 | 3.603 | 3.419 |

### ★★★ 而「159 条」这个数本身是虚高的（10-31 实测）

```
★ 45 条链里,★★★ **只有 32 份独立结果** —— 13 条是同一份配置挂了两个批次标签
  (11 个重复组,其中两组是三胞胎)。★ 去重率 **71.1%**。
★★ 所以 159 条里同样混着重复。按同比例推算,★★★ 真实独立条数 **M ≈ 113**。
★ 这是**推算,不是实测** —— 要准确数字,得把 159 条逐条去重,还没做。
```

**M = 113 时的门槛：双侧 3.513 · 单侧 3.325。**
★★★ **两种口径下 `t ≥ 3.0` 都比 Bonferroni 松** —— ★ 所以它从来不是一个极端值。

### 假阳性对照（按 M = 113，113 条纯噪音能过几条）

| 门槛 | 预期过关条数 |
|---|---|
| 1.96 | 5.65 |
| 2.80 | 0.58 |
| **3.00** | **0.31** |
| 3.419 | 0.07 |

## 第 2 节 · 两个基准

### 基准一 · 随机对照

**问的问题：** 这条策略的选股和择时，比「在同一个池子里随机挑、随机进出」好吗？

```
做法:同一条链的规则不变,把「选哪只票」换成随机,跑 50 个种子,看真链在分布里的位置
```

**★ 两个已修掉的缺陷（2026-10-31）：**

| # | 缺陷 | 实测后果 |
|---|---|---|
| ① | **对照组从来没进大+中池** —— 注释承诺「见下面的 `_patched`」，而那个 `_patched` 根本不存在 | LFMD 同时在可跑 300 只里**和** 53 只「从来不进大+中池」的票里。那 53 只占 **14.07% 笔数但 16.2% 净利润，LFMD 一只占 +39.6%** → 旧对照组能碰到它，真链结构上碰不到 |
| ② | 容差声明 ±8%，但只检查「有没有结果」不检查「差多少」 | 实测超了 **10.42%** / **20.05%** 照样通过 |

**修法（已在 `engine/analyze.py`）：**
- `BenchmarkPremiseBroken` —— 3 个 raise 点，前提破了就报错，不许静默出数
- `CONTROL_TOL = 0.05` —— 容差收到 ±5%，**且检查「差多少」而不是「有没有」**
- `CONTROL_SEEDS` 50 个**常量**（原来是 `20181001 + 977*k` 自生成，已删 —— 自生成的种子等于没登记）
- 两段校准：**验证段算的量就是断言检查的量**（原来是两个量）

### 基准二 · 买入持有

**问的问题：** 这条策略比直接买指数好吗？

**★ 这一道必须带着前提读，否则会得出错的结论。**

实测 0/35 跑赢满仓 SPY。而 2014–2025 是一段超级长牛 ——
**任何带空仓、带止损的策略在这段里几乎 100% 跑输满仓指数**，因为它的止损在上涨段里只会减仓。

所以：

```
✅ 基准二是说明书里的一格 —— 如实写「这段历史里跑输满仓指数」
❌ 基准二不是上线门槛
★ 每条策略还要有它自己的对标(动量策略对标动量指数,不是一律对 SPY),
  最后再和大势对比一次
```

## 第 3 节 · 防作弊协议（★ 这一节是红线）

| 条 | 规则 | 为什么 |
|---|---|---|
| 1 | **预先登记 + Git Tag** —— 登记之后不管结果多惨，**严禁回退** | 不登记就等于可以偷偷重来 |
| 2 | **正交宏观锚点** —— 不许用策略自己的零件定义它的大环境 | 否则「适用环境」会变成「这策略信号多的时候」，循环论证 |
| 3 | **禁止单点估计** —— 必须取 3 个邻近点，**且全部同向** | 单点可能是噪音里的尖峰 |
| 4 | **纯样本外封存** —— 只跑一次 | 跑第二次它就不是样本外了 |

### 第 3 条按字面执行：**2 个同向 1 个反向，算不过。**

今天的实例：技-4 柄长 3→5「改对了成绩变好 +8.91R」—— 加上邻近扫描（6/7/8）后
**非单调**，波幅 5~9R 和改善量同一个量级 → **只给笔数结论，R 层面不给结论**。

### 第 4 条已经用掉了（★ 必须知道的坏消息）

**我们现在没有任何干净的留出池。**

```
时间维度:2022–25 已经反复看过(那个 +5.04 就是那段)  → 污染
股票维度:实测 0 只候选是没碰过的,落到 20% 哈希切分后
         ★ 49/49 = 100% 都已经跑过              → 污染
```

**所以这一批策略只能如实写「未经历史样本外验证」。**

### 唯一干净的留出池：往前走

```
过去的数据我们都看过了,但未来的数据我们还没看过。
→ 把这一批冻结一版(打 tag + 哈希),在纸面模拟盘上跑,不投钱只记账。
→ ★ 从冻结日起的行情,是我们唯一一份真正样本外的数据。
```

## 第 4 节 · 五种「优化」的合法性

| # | 做法 | 判定 |
|---|---|---|
| ① | 修实现错误 | ✅ **合法，而且必须做** |
| ② | 补缺失机制（原著有、我们没实现） | ✅ 有限度 —— **必须全矩阵同步装，严禁选择性补** |
| ③ | **调参数让成绩变好** | ❌ **100% 过拟合 + 合规违规，没有辩解空间** |
| ④ | 换基准 / 换样本区间 | ❌ 重大违规 |
| ⑤ | 下架表现差的 | ⚠️ 可以下架实盘权限，**但不可物理删除**（幸存者偏差 + 重大遗漏） |

**②「必须全矩阵同步装」的意思：** 补一个机制，就给所有 45 条链都装上，
不许只给那几条看起来有救的装 —— 选择性补就是变相调参。

## 第 5 节 · 三道卡口（防止这类错再发生）

今天撞出的错里，有一大类是**机械检查抓不到的**。所以加三道：

### 卡口一 · 契约断言

前提破了就 raise，不许静默出数。已落地：`BenchmarkPremiseBroken`。

### 卡口二 · 10 条策略的标准答案集

挑 10 条策略，把当前结果冻成「标准答案」。**每次改底层先跑这 10 条，结果必须一模一样。**
不一样就说明这次改动动到了不该动的地方。

### 卡口三 · 出处 grep 对账（★ 今天新加，最硬的一道）

```
❌ 旧检查:source 这一栏填了没有
   实测它自己的测试里:source 写「原著(编的)」/「x」/「随便写点什么」—— 全部通过

✅ 新检查:★ 这个数在方法卡原文里 grep 得到吗
   grep 不到的 → 强制标「我们填的」
```

### 还要一条组织上的

**写策略的人和写对照检查的人分开。** 自己检查自己，查不出来。

## 第 6 节 · 已知会骗人的几个坑（实测，照单避开）

| 坑 | 实测 |
|---|---|
| **「30 周 ≈ 150 个交易日」** | ❌ 真实每周平均 **4.8134** 天，30 根周线只覆盖 **144.61**（中位 145），差 5.39 天。换成 SMA145/回看 48 后，「周线领先」**精确归零**（中位 −4.0 → 0.0，82.4% → 41.5%） |
| **同一样东西两种写法** | 已撞 **28 处**。最新一处：`buy_and_hold` 的 `initial_stop` 写成 `{type: pct, pct: 0.999}`，source 写「等价于不设止损」—— **机械检查抓不到**。无止损链真实是 **5 条**不是 4 条 |
| **阈值有两份权威副本** | 技-3/4/5/6/11/14 的配置是 `engine/pat6_make_configs.py` **生成**的。只改 yaml，跑一次生成器**静默冲掉**，而 git diff 看起来只是「重新生成了一下」 |
| **同一个名字两条规则** | `pullback_to_ma` 有两个派发器。那一版**只读 4 个参数里的 1 个**，判的是「收盘下穿 SMA50」而不是配置写的「从 20 日高点回踩到 ±1.5×ATR14」 |
| **参数位置不统一会静默吃掉设置** | `regime_mask()` 里 `index_above_ma`/`vix_below` 只读顶层；`index_ma_slope` 读 `params`。→ `index_above_ma` 写在 `params` 里**不报错，静默退回默认值 SPY/200** |
| **「stage」四种含义** | `matrices.stage_ma`（分级止损均线）· `sizing.stages`（分批建仓）· 技-5 的 `stage: selection_gate`（漏斗关卡）· 状-2 阶段号 |
| **代号不一致对丢流水** | 池子用 `ANTM`、流水用 `ELV` → 曾对丢 **8,554 笔**（5.8%），几乎全是小票。而 `*ledger*` 一把捞会多出 54 个 breakeven 副本 |
| **拼表把两条链的数拼成一张** | 技-1 的「364 笔」属 System 2（实际**赢**随机 +0.070R），「−0.323R」属 System 1（547 笔）。根因：上一轮汇总表把 System 2 的值印成了破折号 `—` |
| ★★★ **同一份配置挂两个批次标签** | 45 条链里**只有 32 份独立结果**，13 条是副本（11 个重复组，两组三胞胎）。★ 任何「几条链怎样了」的计数都会虚高，**包括多重检验的条数** |
| ★★★ **`.gitignore` 放在子目录里要写成另一种样子** | 带路径前缀的模式放进子目录的 `.gitignore` **一条都不匹配，而且不报错** —— 642MB 原始流水因此又被提交了一次。★ 和 `index_above_ma` 写在 `params` 里静默退回默认值是同一个毛病 |
| ★★★ **退化 R —— 一个分母可能为零，而代码里没有下限** | 止损价落在进场价上 → 1R = 0 → 那一笔 R = **1.75e14** → 一笔毁掉 50 个种子的均值，技-10 的基准一被算成 **−31 亿**。★★ 代码里**本来就有** `risk > 0` 的防护，挡不住 risk 是**极小正数**（浮点残差）的情况。★★★ **这一类会在任何比率型指标上再犯** —— R、胜率、盈亏比，凡是有分母的都要有下限 |
| ★★★ **`--only` 部分重跑会静默覆盖全量汇总** | 45 条的汇总被覆盖成只有 3 条。★ 逐链 json 还在所以能重建（不带 `--only` 再跑一次，全部走断点，0 秒），★★ 但没注意的话，下一个人看到的就是「我们只跑了 3 条」 |
| ★★★ **一个破折号同时表示三件事** | `—` 被当成「真的没有这个数」「算出来了但不许当结论」「前提破了」。★★ 技-1 原著 System 2 的基准一实际 **+0.070（赢随机）**却被印成 `—`。★★★ 更严重的是**被闸挡下的链整条从表里消失** —— 消失了没人知道它存在过。★ 修法：值不是空的却渲染成 `—` → 直接 raise |
| ★★★ **单侧 / 双侧没标** | 我们报过 Bonferroni 门槛 3.205 / 3.224 / 3.419，**那是单侧的数，当时没标**。★ 双侧分别是 3.399 / 3.417 / 3.603。★★ 同一样东西两种口径，不标清楚就会被当成同一个数引用 |

## 第 7 节 · 跑批纪律

```
□ 不用 `nohup &`           —— 子进程被静默杀,没有 traceback
□ 先做可续跑               —— 每条链单独 dump。实测 8 分钟 → 几秒
□ 先量 2~3 条耗时再开全量   —— 这台机器 2 核 8GB
□ ★ 先写结果再打印          —— 曾丢 437 秒跑批,因为拼错的 print 键在 JSON 写出前触发
□ ★ 说「已经开跑」之前,先确认它真的在跑
```

## 第 8 节 · 对外说话

```
❌ 「这些方法已经失效」
✅ 「这些方法在我们的实现上没有通过检验」
```

**凡对外说某方法「失效」，必须先过保真度检查。** 实测乙类不一致 **55 处**，
其中 **7 条疑似是我们自己的实现错误** —— 那 7 条说「失效」说的是我们自己。
