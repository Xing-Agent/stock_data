## ★★★ 图里第 ① 条是什么意思

```
★★★ **他不说想怎么做之前，我们没法告诉他该用哪个策略。**

★★ 为什么 —— 举个例子,同一只票、同一天、同一个结构:
   ★ 对**做短线**的人:「它来回折腾、量能不足」→ 这是**坏环境**
   ★ 对**做震荡**的人:「它来回折腾」→ ★★★ 这恰好**正是他要的环境**

★★★ 所以在用户说出「我打算怎么做」之前,
   ★ 我们如果说「这只票现在不好」—— ★★ 那是我们**替某一类做法**
     去贬低一个**客观状态**,而我们并不知道他是哪一类。
→ ★★★ 所以他**认领一个做法**那一刻（第 6 屏那个 A / B 场景）,
   才是我们**能开口说「该用哪个」**的那一刻。

★★ 在那之前我们能做什么:**摆事实** ——
   ★ 现在的状态是什么、关键位在哪、★★ **哪些方法的前提成立、哪些不成立**
   (★★★ 注意:摆出「哪些成立」**不等于**告诉他该用哪个 —— 挑哪个是他的动作)。
★★★ 在那之后多出来什么:★ 可以说「**配不配你那套做法**」(第 8 屏那三类)。
★ 任何时候都不给的:★★★ **买卖指令**。

★ (★★ 这件事我们内部叫「**绑定即授权**」—— ★★★ 对外、对团队一律用上面那句话,
   **不要用这个词**,它不解释自己。)
```

★★ **这张图里另一条最容易被忽略的**：★★★ **「下单之后 → 持仓复盘」是闭环。** ★ 没有它，用户的生命周期在下单那一刻就断了。

## ★★★ 为什么目的不是「帮他解套」

```
★ 「怎么解套」这个问题,★★ 在他**没有规则**的情况下无法回答 ——
★★★ 因为任何答案都只是我们替他赌一次,而赌错了是他的钱。
★ 所以这个门交付的不是一个动作,是**一次认知**:
  ★★ 「你当时为什么买、准备拿多久、什么情况下认错」这三个问题他答不出来 ——
  ★★★ **那就是被套的真正原因,不是选错了票。**
```

## ★★★ 「用户就是要一个方案」怎么办（★ Lin 问的，★★ 这一条有明确规定）

```
★★★ **不给的只有一样:「该割、该扛、还是该补」这三选一** —— 那是买卖指令,
   ★ 共用边界里写死了:**任何情况都不给买卖指令。**
★★★ 但「不给方案」**绝不等于**「回一句我不能提供」——
   ★★ 共用边界 §6.3 为这件事专门写了一节,原话:
```

> 「**不给个性化买卖点是对的；不解释原理是另一件事，而且是错的。**
> ★ 前者是合规边界，★★★ 后者是我们欠用户的。」

★ 那一节还写明了**必须给什么**（叫「出口」），**四样**：

| 要给 | 在「我被套了」这个场景里长什么样 |
|---|---|
| ★★ **这套方法要求什么** | 「你当时那个买入逻辑，要求的是 ××（比如：放量突破之后站稳）」 |
| ★★★ **现在卡在哪一条** | 「现在**第 ② 条不成立**了 —— 量能已经连续 N 天低于均量」 |
| ★★ **差多少** | 「要让它重新成立，需要 ××；现在距离 ××」 |
| ★★★ **这条方法的代价是什么** | 「这类做法的历史形状是：胜率 ××%、最长连亏 ×× 次」 |

★★ 如果他**认领了一个场景**（第 6 屏那个 A / B），还能多给三类：★ **配不配** · **触发清单** · **赔率够不够**（见第 8 屏）。

## ★★★ 一条顺序上的硬要求（★ 这一条很容易做错）

```
★ 这个门的目的是「让他自己看见**我当时没有规则**」——
★★★ 但如果用户**开口就是要方案**,★ 你**先**说这句话,
   ★★ 它听起来就是**说教**:「你自己没规则,怪谁呢」。
★★★ 所以顺序必须是:
   ① **先给上面那四样出口** —— 他现在就能用的东西
   ② 再(如果合适)才说规则那件事,★ 而且说法是
      「**下次要不要我们帮你把这几条先定下来**」,不是「你当时没定」
★ 一个是**往前看的提议**,一个是**往后看的评判** —— ★★ 内容一样,但后者会赶走用户。
```

★★ **V2 和 V3 的差别就在这个门上最大**：★ V2 只有「行情的持仓分支」+ 上面这套出口；★★★ 完整的解套流程（四个问题 + 急救段）在 `V3设计-第六版` 第 3 站，**V2 没有**。
