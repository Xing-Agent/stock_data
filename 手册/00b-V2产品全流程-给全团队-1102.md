# 第 2 屏 · 用户从哪里进来（四个门）

| 他想干什么 | 落到哪 |
|---|---|
| ★ 「我有一只票，想看看」 | **行情 / K线互动** |
| ★★ 「我被套了，不知道怎么办」 | **行情**（持仓分支） |
| ★ 「今天市场什么情况」 | **行情**（大盘视图） |
| ★★★ 「我想找点能做的」 | **股票筛选** ⚠ 带限定，见下 |

## ⚠ 选股这个门有一条必须说出来的限定

```
★ 我们**没有**「标普 500 当年有哪些票」这种历史成分名单。
★★ 但我们**有**一个自己切的股票池:**74,268 行,每年约 6,000 只**,
   ★ 按年初前 60 个交易日的日均成交额排名切成大/中/小三带,
   ★★★ **按段不按代码,所以含退市股、没有生存者偏差**。
★★★ 所以选股**不是做不了**,是**不能按指数成分选,只能按我们这个池选** ——
   ★ 这件事必须在界面上说清。
★★ 而「大盘股」在这里的意思是「**成交额前 500**」,不是「标普 500 成分股」。
★ 还有一条:★★★ 小盘带里**一半多日成交额不到 100 万美元** ——
   ★ 下单那一刻必须有成交额门槛把关,否则**回测买得到、实盘买不到**。
```

★★★ 原则一句话：**做一个假的选股入口糊弄，会毁掉「专业」这个第一印象 —— 而第一印象只有一次。**

# 第 3 屏 · 进来之后，请求怎么找到它该去的地方

| 用户在做什么 | 走哪里 |
|---|---|
| 点名了某位大师（「用温斯坦的方法看看」） | 那位大师的方法卡 |
| ★★★ **技术面问题但没点名大师**（「什么阶段」「止损放哪」） | **技术面大师**（通用能力） |
| 基本面问题但没点名 | 按**问题**匹配方法，★ 不按人名加载 |
| 从一堆标的里找 | 股票筛选 |
| 看一只票、看 K 线 | 行情 / K线互动 |
| ★ 「帮我盯一下**某只票**的某个条件」（**有标的**） | 创建 agent |
| ★ 「我想找**所有**符合某条件的」（**没标的**） | 创建技能 |
| ★★ **已经买了，想知道现在怎么样** | **持仓与 agent 复盘** |

## ★★★ 最容易漏的一条

```
★ 用户问技术面问题而**没点名大师** —— ★★★ **不要落到某个大师镜头上。**
★ 「NVDA 什么阶段」不是在问温斯坦,是在问一个通用能力。
★★★ 落到温斯坦卡上,等于**替用户选了方法** —— 而选方法是他的动作。
```

## ★ agent 和技能怎么分

```
★ 判据只有一条:**他说的里面有没有具体标的。**
   有标的 = 他要一个**实例**(agent)
   没标的 = 他要一条**可复用的规则**(技能)
★★★ **用户永远不需要知道这两个词** —— 入口统一,底下分流。
```

# 第 4 屏 · 两个分叉 —— ★★★ 不分，答案就是错的

## ★★ 分叉一 · 他**已经持仓**，还是**还在看**

```
★★★ 同一个问题,这两种情况下**答案和说话方式完全不同**。
★ 「NVDA 现在怎么样」——
   还在看  → 摆条件、摆空间、摆失效位
   已持仓  → ★★ 他真正在问的是「我该不该继续拿着」,这是另一个问题
```

## ★★ 分叉二 · 他问的是**现在**、**历史**，还是**假设**

```
★ 「现在什么阶段」      → 当下状态
★ 「去年这时候什么阶段」 → ★★ 历史回放,★★★ **必须用当时能拿到的数据**(时点口径)
★ 「如果跌到 X 会怎样」  → 假设推演,★★ 必须标明「这是推演不是预测」
```

★★★ 这两个分叉是**路由的一部分**，不是回答时的修饰 —— ★ 分错了，后面每一句都偏。

# 第 5 屏 · 有一类问题**必须先反问**（★★★ 而反问是流程的一步）

★ 最典型的一句：**「这公司好不好，现在能买吗」**

```
★★ 前半能答。★★★ 后半**不能答** ——
★ 而且不是「这个问题太难」,是:★★★ **它在当前状态下无法回答,
  因为答案取决于用户用什么方法。**
```

## ★ 正确的处理长这样

> 「这公司好不好」—— 这个我能答（基本面事实）。
>
> 「现在能买吗」—— **这取决于你用什么方法。**
> 你打算拿多久？最多能忍多大浮亏？
> 告诉我这两个，我就能说这个位置**配不配你那套做法**。

```
★★★ **反问不是推脱，是解锁权限的必要步骤。**
★ 没有那两个声明,系统连「配不配」都**无权**评价 ——
★★ 因为同一个状态,对做震荡的人可能正是**好环境**。
```

★★★ 所以「顶级顾问更主动」的准确含义是：**不是主动给建议，是主动去拿那些声明。**

# 第 6 屏 · ★★★ 权限是用户给的（绑定即授权）

| 用户说了什么 | 系统获得什么 |
|---|---|
| **什么都没说** | ★ 只能给**条件推演**，不能对这只票下定性 |
| ★★★ **说了做单类型 + 单笔承受度** | ★★ **获得审计权** —— 可以评价「这个结构配不配你这套做法」 |
| **任何情况** | ★★★ **都不给买卖指令** |

## ★★ 解锁之后才能说的三类（★ 之前一句都不能说）

```
★ ① **配不配**   —— 「你说的突破做法,在当前结构下没有统计优势」
★ ② **触发清单** —— 「现在不满足。三个条件同时达成才算启动:① ② ③」
★ ③ **赔率够不够** —— 「失效位必须放在 X,上方第一个阻力在 Y,赔率 0.67:1」
```

★★★ **为什么没声明时不能说：** 同一个状态对做震荡的人可能正是好环境；0.67:1 的赔率对高频剥头皮可能完全可以接受。★★ **没有用户的声明，我们无权替某一类做法去贬低一个客观状态。**

## ★ 还有一层：用户挑「策略」时，挑的只有第三层

| 层 | 是什么 | ★ 谁管 |
|---|---|---|
| 一 · 标的池 | 在哪些票里找 | 筛选 |
| ★★ 二 · **状态判定** | 现在是什么情况 | ★★★ **安检门，不是货架上的商品** |
| ★★★ 三 · **信号发生器** | 什么时候做 | ★ **用户挑的就是这一层** |
| 四 · 组合构建 | 各买多少 | |
| 五 · 执行 | 怎么下单、怎么出 | |

```
★★★ 第二层**绝对不能**作为候选策略推给用户。
★ 用户说「我想做突破」,系统**不该**把「温斯坦四阶段判定」当成一个选项推给他 ——
★★ 正确做法是**先用它算出现状**,然后告诉他「在这个状态下,突破类的假信号率是多少」。
```

# 第 7 屏 · 呈现那一条硬规则（★★★ 一眼就能判对错）

★ V2 的呈现**照搬**这个形状：

```
哪些方法的前提条件现在成立:
  ×  突破类     需要趋势效率 > 0.6    现在 0.22
  ×  回调买入   需要温斯坦阶段二      现在阶段三
  ✓  区间往返   需要区间 ≥ 20 天      第 31 天
  ×  趋势跟随   需要日线方向明确      现在震荡
```

## ★★★ 规则本身：不说「适合」，说「哪些前提成立」

| | |
|---|---|
| ❌ | 「适合你的策略：突破交易（**匹配度 85%**）」 |
| | ★ 两条都违规：**这是推荐**，而且 **85% 是我们合成的分** |
| ✅ | 「突破类需要趋势效率 > 0.6，现在 0.22，**不成立**」 |
| | ★★★ 这是**检查结果** —— **判断是他的。** |

## ★★ 排序那一条

```
✅ 「基于**你所选体系**下的适配度排列」
❌ 「优劣排序」
★★★ 用户**没选体系** → **不排序**,按出处等级分组展示。
```

★ 还有一条跨流派的：★★★ **同一流派内部的代价数字才可比，跨流派比是有害的。** ★ 拿突破的胜率去和均值回归的胜率排序，会把前者永远排在后面 —— ★★ 而那**不是它差，是它本来就长那样**。

```
★★ 实测佐证:同一套温斯坦入场,
   配**紧**止损 → 胜率 31.2%(突破形状)
   配**宽**止损 → 胜率 41.5%(趋势跟随形状)
★★★ 所以决定一条策略属于哪个流派的,**不只是入场,还有止损** ——
   ★ 两条止损路径不是「同一策略的两个选项」,是**两条不同流派的策略**。
```

# 第 8 屏 · 说话分两档，而且方向相反

| 档 | 哪些地方 | 怎么说话 |
|---|---|---|
| ★★ **看市场** | 筛选 · 行情 · 所有大师卡 | ★★★ **克制** —— 摆事实和条件，**方向判断归用户** |
| ★★ **搭工具** | 创建 agent · 创建技能 | ★★★ **主动** —— 该给建议就给，**而且应该给** |

```
★ 为什么反向:★★ 看市场时他在做判断,我们不该替他判断;
★★★ 搭工具时他在做工程,而工程上有对错 —— 这时候不给建议才是失职。
```

## ★ 给多少：按他要做的决定给，不按我们有多少

```
★★★ **注意力是预算。**
★ 我们已经在很贵的地方花过了(★★ 大量时候我们要说「这套方法现在不成立」)——
  ★★★ 界面上就得省着花。
★ 三条:① 渐进式展开,★★ 而展开的依据是「**他要做什么决定**」,不是内容的重要性
       ② 不要把所有信息平铺 —— ★ 顶级助理 present 时不会把全部材料摊在桌上
       ③ ★★ 用户明确要求看全部时,**给全部**
```

# 第 9 屏 · 闭环：下单之后

```
★ 四个交界处:
   筛选 →(点进一只票)→ 行情
   行情 →(「帮我盯着」)→ agent
   agent →(同一条件用了三次)→ 技能
★★★ **下单之后 → 持仓复盘**

★★★ 最后那一条是闭环。**没有它，用户的生命周期在下单那一刻就断了。**
```

# 第 10 屏 · ★★★ 答不了的时候（★ 这一屏藏着一道闸）

| 类 | 是什么 | 怎么处理 |
|---|---|---|
| **一** | ★ 可以编码，只是还没做 | 临时交给外部模型，★★ **标注来源**，同时进待编码清单 |
| **二** | ★ 原理上归语言模型（理解含糊提问、讲人话） | 长期如此，不用改 |
| ★★★ **三** | ★★ **我们定了不答的** | ★★★ **绝不交给外部模型兜底** |

## ★★★ 第三类是一道闸，这道闸不能漏

```
★ 用户换个问法,就能从外部模型拿到**我们禁止输出的东西** ——
★★★ **而他看到的还是我们的界面。**
```

★★ 所以兜底**不是转接，是转接 + 过滤 + 标注**：★ 五道卡口 · 四类分诊（只有「真的不会」才兜底）· 红线五类**含中文别名** · ★★★ **原著计分白名单例外**（F-Score 给 9 分不许拦）。

## ★ 第一类那个数，是我们最该盯的指标

```
★★★ **第一类的条目数，就是「我们离完整还有多远」那个数。**
★ 它会随着编码推进**自己减少**,★★ 而且它是**用户的真实问题驱动的** ——
★★★ 比我们自己猜该补什么强得多。
★ 目标:兜底占比 ≤ 20%(★★ 完整度 = 我们自己答的 ÷ 总问题数)
```

# 第 11 屏 · ★★★ V2 现在哪里是断的（★ 这一屏不许跳过）

```
★★★ 一 · **「到价提醒我」还没做**（条件引擎）。
   ★ 所以界面和文案里**不许出现「会提醒你」**。
   ★★ 要写就写「**你自己定个日子回来看**」。
   ★★★ 原话:「平台不能提醒,而文案里写了『会提醒你』—— **那是平台在骗他**。」

★★★ 二 · **兜底那条路技术组还没接。**
   ★ 所以现在「答不了」就是真的答不了,不会转给外部模型。
   ★★ 第 10 屏那三类**分诊逻辑已经定了,但管道还没通**。

★★★ 三 · **说明书的样本外那一格是空的。**
   ★ 考卷正在跑(1,026 只我们从没碰过的票)。
   ★★ 所以:★★★ **现在不许对外说任何一条策略「经过样本外验证」。**

★★★ 四 · **代价那一格（最大亏多少美元）也是空的。**
   ★ 卡在逐笔流水没入库。★★ 加上样本外那一格 ——
   ★★★ **严格讲，现在一条策略都还不能出厂。** ★ 这不是悲观,是把门槛当门槛。

★★★ 五 · **45 条策略里有 40 条，一个大盘开关都没装。**
   ★ 方法卡明写要装(「熊市不该用」「震荡市不该用」),而配置里是空的。
   ★★★ 所以别人问「这些策略在熊市会不会被挡住」—— ★ 答案是**不会**。

★★★ 六 · **基本面大师卡里有两步是我们主动停用的**(估值、护城河那两步)。
   ★ 利率数据已经到了,★★★ **停用的理由不是缺数据** ——
   ★ 是因为「所有公司用同一个折扣率」在数学上**不改变排序**,
   ★★ 算了也不改变我们交给用户的顺序,★★★ 不值得为它背一个「长得像事实的编造数字」。

★★★ 七 · **屏级设计（第一屏长什么样、按钮放哪）在 V3 第六版里，不在 V2。**
   ★ V2 定的是**流程和规矩**,★★ V3 定的是**那条路上每一站的样子**。
```
