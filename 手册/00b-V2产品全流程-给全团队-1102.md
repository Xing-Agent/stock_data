```
   「NVDA 现在怎么样」
          │
          ▼
   ★★ 先分两个叉（不分，答案就是错的）
          │
    ┌─────┴─────┐                ┌──────────┬──────────┐
    ▼           ▼                ▼          ▼          ▼
 还在看      已持仓            问现在     问历史     问假设
    │           │                │          │          │
    ▼           ▼                ▼          ▼          ▼
 摆条件      他真正在问的是    当下状态   ★★ 必须用   ★★ 必须标
 摆空间      「我该不该         │      当时能拿到的  「这是推演
 摆失效位     继续拿着」        │        数据       不是预测」
                               ▼
                    ★★★ 呈现:不说「适合」,说「哪些前提成立」
```

## ★ 这个门给什么

★★ **单只票的状态 · 关键位 · 空间 · 失效位 · 量价**，以及和 K 线图的互动。

## ★★★ 这个门自己的六条禁令（★ 每一条都是踩过的）

```
★ 一 · **K 线上画条件线，不标成交价。** 画的是「条件成立的位置」,不是「你该在这儿买」。
★ 二 · **三条线的名字固定:条件线 / 证伪线 / 兑现线。** 不许换说法。
★★★ 三 · **失效位必须说清「收盘算还是盘中触及算」。**
     ★ 同一条线两种算法完全不同,★★ 而用户默认以为是盘中。
     ★★★ 不说清楚,他会**盘中被扫出去、收盘却根本没破** —— 这是会直接造成亏损的一条。
★★ 四 · **空间要给两个数:目标价位 + 净空间百分比**(扣掉买卖价差之后)。
     ★ 只说「上方有空间」,用户算不了赔率。
★ 五 · 不说「适合」,说「哪些前提成立」。
★★★ 六 · **状态判定不是可选的策略。**
     ★ 用户说「我想做突破」,不要把「温斯坦四阶段判定」当成一个选项推给他 ——
     ★★ 先用它算出现状,再说「当前阶段四,突破类的历史假信号率是 X%」。
     ★★★ **它是安检门，不是货架上的商品。**
```

# 第 4 屏 · 门二 · 「我被套了，不知道怎么办」

```
   「我 XX 买的，现在亏 30%，怎么办」
          │
          ▼
   ★ V2 走的是**行情的持仓分支** —— ★★ 和「还在看」是两套说法
          │
          ▼
   ★★★ 这个门的目的**不是帮他解套**
          │
          ▼
   ★★★ 是让他自己看见「**我当时没有规则**」
          │
          ▼

```

## ★★★ 为什么目的不是「帮他解套」

```
★ 「怎么解套」这个问题,★★ 在他**没有规则**的情况下无法回答 ——
★★★ 因为任何答案都只是我们替他赌一次,而赌错了是他的钱。
★ 所以这个门交付的不是一个动作,是**一次认知**:
  ★★ 「你当时为什么买、准备拿多久、什么情况下认错」这三个问题他答不出来 ——
  ★★★ **那就是被套的真正原因,不是选错了票。**
```

★★ **V2 和 V3 的差别就在这个门上最大**：★ V2 只有「行情的持仓分支」；★★★ 完整的解套流程（四个问题 + 急救段）在 `V3设计-第六版` 第 3 站，**V2 没有**。

# 第 6 屏 · 门四 · 「我想找点能做的」（★★ 这个门最复杂）

```
   「有什么能做的」
          │
          ▼
   ★★★ 先问三个**他答得出来**的问题（★ 不问技术参数，不问偏好）
     ① 你能什么时候看盘?        ← ★★ 物理约束,一票否决他执行不了的策略
     ② 面对亏损,你更厌恶哪种痛苦? ← ★★★ 整套引导的关键设计,见下
     ③ 这笔钱最长多久必须抽走?    ← ★ 击碎「拿短线的钱做长期价值投资」的幻觉
          │
          ▼
   ★ 三个问题答完,**筛选条件自动生成。引导到此结束,不要再追问。**
          │
          ▼
   ★★ 从池子里筛 → 排序 → 呈现
          │
          ▼
   ┌────────────────────────────────────────────────┐
   │ 当前池子:300 只 · 符合条件 7 只                │
   │      标的  前提成立  不成立的那条  上方空间  最大浮亏 │
   │      XXX    8/10    相对强弱为负   +4.2%   -6.9%  │
   └────────────────────────────────────────────────┘
          │
          ▼
   点进一只票 → ★ 回到门一（行情）
```

## ★★★ 第二问是整套引导的关键设计（★ 这一条值得全团队看懂）

```
❌ 不要问「你想要机会多一点还是准一点」
   ★★★ —— **100% 的人会说「准一点」**,因为没人会主动选「不准」。
   ★ 那样系统会把所有用户标记成高胜率偏好,
   ★★ 全量推给他们**高胜率、极低赔率、左尾暴雷**的极限均值回归策略 ——
   ★★★ 遇到一次单边大跌,**一单亏光一年利润**。

✅ 问「**你更厌恶哪种痛苦**」:
   A **钝刀子割肉** —— 经常小止损,但绝不扛大亏   → 指向均值回归(高胜率低赔率)
   B **坐过山车**   —— 能忍账面缩水一大块,但绝不能把看好的票洗掉 → 指向趋势跟随(低胜率高赔率)

★★★ **两边都是痛苦,没有正确答案** —— 这才问得出真实偏好。
★★ 一句话:**人对痛苦的偏好是真实的，对「好」的偏好不是。**
```

## ★★★ 答不了「现在能买吗」时：给两个带代价的场景，不要问参数

```
★★★ **严禁反问数字**（「你能忍多大浮亏?」）。
★ 散户的真实反应是:「我要是懂怎么定浮亏还要你干嘛?」——
  ★★ 然后关掉 App,或者随手填一个数糊弄,★★★ 第二天跌 3% 就恐慌割肉并投诉我们误导。

✅ 给两个**带真实代价**的场景让他认领:
   A · **快进快出**   —— 止损卡在现价下方 2%,胜率不高,
        ★ **可能要连续止损两次才抓到一次启动**
   B · **大波段持有** —— 拿两三个月,不理会盘中杂音,
        ★ **但中间要做好承受 12% 浮动回撤的心理准备**

★★ 他点 A 或 B → 系统后台翻译成参数,**权限无缝解锁,没有填空题**。
★★★ 场景里的数字**必须是我们实测出来的,不能编**。
```

## ⚠ 这个门有一条必须说出来的限定

```
★ 我们**没有**「标普 500 当年有哪些票」这种历史成分名单。
★★ 但我们**有**一个自己切的股票池:**74,268 行,每年约 6,000 只**,
   ★ 按年初前 60 个交易日的日均成交额排名切成大/中/小三带,
   ★★★ **按段不按代码,所以含退市股、没有生存者偏差**。
★★★ 所以选股**不是做不了**,是**不能按指数成分选,只能按我们这个池选**。
★★ 「大盘股」在这里的意思是「**成交额前 500**」,不是「标普 500 成分股」。
★★★ 还有一条:**小盘带里一半多日成交额不到 100 万美元** ——
   ★ 下单那一刻必须有成交额门槛把关,否则**回测买得到、实盘买不到**。
```

★★★ 原则一句话：**做一个假的选股入口糊弄，会毁掉「专业」这个第一印象 —— 而第一印象只有一次。**

# 第 7 屏 · 从四个门出去之后：agent / 技能 / 复盘

```
     行情 ──「帮我盯一下 **NVDA** 的某个条件」──►  agent（有标的 = 一个实例）
                                                      │
     筛选 ──「我想找 **所有** 符合某条件的」──────►  技能（没标的 = 一条可复用的规则）
                                                      │
                 agent ──（同一条件用了三次）──────►  技能
                                                      │
                                   下单 ──────────►  ★★★ 持仓复盘（闭环）
```

## ★ 分流判据只有一条

```
★★★ **他说的里面有没有具体标的。**
   有标的 = 他要一个**实例**(agent)
   没标的 = 他要一条**可复用的规则**(技能)
★★★ **用户永远不需要知道这两个词** —— 入口统一,底下分流。
```

## ★★ 复盘这个门为什么是闭环

```
★ 它管的是「**已经买了 / 已经配了 agent,想知道现在怎么样**」。
★★★ 没有它,用户的生命周期在下单那一刻就断了 ——
   ★ 而「买完之后呢」恰好是散户最没人管的那一段。
```

★★ 另外，`xing-skill-builder`（让用户定义自己的条件）是**八张卡里风险最高的一张** —— ★ 因为它让用户自己造规则，★★★ 而一条用户自己造的规则，我们**没有测过**。

# ★★★ 第 8 屏 · 全程规矩一 · 权限是用户给的（绑定即授权）

| 用户说了什么 | 系统获得什么 |
|---|---|
| **什么都没说** | ★ 只能给**条件推演**，不能对这只票下定性 |
| ★★★ **认领了一个场景（A / B）** | ★★ **获得审计权** —— 可以评价「这个结构配不配你这套做法」 |
| **任何情况** | ★★★ **都不给买卖指令** |

## ★★ 解锁之后才能说的三类（★ 之前一句都不能说）

```
★ ① **配不配**   —— 「你说的突破做法,在当前结构下没有统计优势」
★ ② **触发清单** —— 「现在不满足。三个条件同时达成才算启动:① ② ③」
★ ③ **赔率够不够** —— 「失效位必须放在 X,上方第一个阻力在 Y,赔率 0.67:1」
```

★★★ **为什么没声明时不能说这三类：** 同一个状态，对做震荡的人可能正是**好环境**；0.67:1 的赔率对高频剥头皮可能完全可以接受。★★ **没有用户的声明，我们无权替某一类做法去贬低一个客观状态。**

## ★ 还有一层：用户挑「策略」时，挑的只有第三层

| 层 | 是什么 | ★ 谁管 |
|---|---|---|
| 一 · 标的池 | 在哪些票里找 | 筛选 |

| ★★★ 三 · **信号发生器** | 什么时候做 | ★ **用户挑的就是这一层** |
| 四 · 组合构建 | 各买多少 | |
| 五 · 执行 | 怎么下单、怎么出 | |

# ★★★ 第 9 屏 · 全程规矩二 · 不说「适合」，说「哪些前提成立」

★ V2 的呈现**照搬**这个形状：

```
哪些方法的前提条件现在成立:
  ×  突破类     需要趋势效率 > 0.6    现在 0.22
  ×  回调买入   需要温斯坦阶段二      现在阶段三
  ✓  区间往返   需要区间 ≥ 20 天      第 31 天
  ×  趋势跟随   需要日线方向明确      现在震荡
```

| | |
|---|---|
| ❌ | 「适合你的策略：突破交易（**匹配度 85%**）」 |
| | ★ 两条都违规：**这是推荐**，而且 **85% 是我们合成的分** |
| ✅ | 「突破类需要趋势效率 > 0.6，现在 0.22，**不成立**」 |
| | ★★★ 这是**检查结果** —— **判断是他的。** |

## ★★ 排序那一条

```
✅ 「基于**你所选体系**下的适配度排列」
❌ 「优劣排序」
★★★ 用户**没选体系** → **不排序**,按出处等级分组展示。
```

## ★★★ 还有一条：跨流派比胜率是有害的

```
★ 同一流派内部的代价数字才可比。
★★ 拿突破的胜率去和均值回归的胜率排序,会把前者**永远排在后面** ——
★★★ 而那**不是它差,是它本来就长那样**。

★★ 实测佐证:同一套温斯坦入场 ——
   配**紧**止损 → 胜率 **31.2%**(突破形状)
   配**宽**止损 → 胜率 **41.5%**(趋势跟随形状)
★★★ 所以决定一条策略属于哪个流派的,**不只是入场,还有止损** ——
   ★ 两条止损路径不是「同一策略的两个选项」,是**两条不同流派的策略**。
```

# 第 10 屏 · 全程规矩三 · 说话两档，方向相反

| 档 | 哪些地方 | 怎么说话 |
|---|---|---|
| ★★ **看市场** | 筛选 · 行情 · 所有大师卡 | ★★★ **克制** —— 摆事实和条件，**方向判断归用户** |
| ★★ **搭工具** | 创建 agent · 创建技能 | ★★★ **主动** —— 该给建议就给，**而且应该给** |

```
★ 为什么反向:★★ 看市场时他在做**判断**,我们不该替他判断;
★★★ 搭工具时他在做**工程**,而工程上有对错 —— 这时候不给建议才是失职。
```

## ★ 给多少：按他要做的决定给，不按我们有多少

```
★★★ **注意力是预算。**
★ 我们已经在很贵的地方花过了(★★ 大量时候我们要说「这套方法现在不成立」)——
  ★★★ 界面上就得省着花。
★ 三条:① 渐进式展开,★★ 而展开的依据是「**他要做什么决定**」,不是内容的重要性
       ② 不要把所有信息平铺 —— ★ 顶级助理 present 时不会把全部材料摊在桌上
       ③ ★★ 用户明确要求看全部时,**给全部**
```

# ★★★ 第 11 屏 · 答不了的时候（★ 这一屏藏着一道闸）

| 类 | 是什么 | 怎么处理 |
|---|---|---|
| **一** | ★ 可以编码，只是还没做 | 临时交给外部模型，★★ **标注来源**，同时进待编码清单 |
| **二** | ★ 原理上归语言模型（理解含糊提问、讲人话） | 长期如此，不用改 |
| ★★★ **三** | ★★ **我们定了不答的** | ★★★ **绝不交给外部模型兜底** |

## ★★★ 第三类是一道闸，这道闸不能漏

```
★ 用户换个问法,就能从外部模型拿到**我们禁止输出的东西** ——
★★★ **而他看到的还是我们的界面。**
```
