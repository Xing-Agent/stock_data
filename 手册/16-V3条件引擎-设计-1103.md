## ★★★ 0 · 范围:这一份只管「叫他」;「替他做」见 0.5 节(Lin 2026-11-04 定)

```
★★★ 条件引擎解决的是「**什么时候叫他**」。
★★  而「助理能力」还有另一半:「**替他做**」。
★★★ Lin 2026-11-04 定调:「**在授权后可以的,最好是自己的 agent。**」
```

### ★★★ 0.5 · 「替他做」的形状(★ 这一条解掉了一条我以为更难的红线)

★★ 我原来的判断:「替他做」撞的红线比条件引擎更难,★★★ 建议 V3 第一版不做。
★ **Lin 的裁定改掉了这个判断**,而且比我那一版干净:

```
★★★ 我们的系统:给依据 · 叫他 —— **从不动手**
★★★ 他的 agent:他授权了,**可以动手** —— 而且措辞、规则都是他的
★★  这两件事的分界线就一个字:**授权**
```

★★★ **为什么这一刀切得对**:动手的**不是我们,是他的 agent** ——
★ 所以「不替他下结论」那条红线**没有被碰**;★★ 我们提供的仍然只是依据和能力,
★★★ 而「要不要让一个 agent 按我的规则替我动手」**是他对自己的授权**,不是我们对他的判断。

#### ★★ 授权的粒度(★ 这是这一节唯一要定清的事)

| 粒度 | ★ 判定 |
|---|---|
| ❌ **一次性全权**(「我的 agent 可以买卖」) | ★★★ **不行** —— ★ 和「我们替他下结论」实质上没差别,只是换了个执行者 |
| ❌ **逐个动作都要他点** | ★ 不行 —— ★★ 那就不是助理了,等于没做 |
| ✅ ★★★ **按规则 + 按限额授权** | ★★ 「这个 agent 可以**按我定的这几条规则**,在**这几只票**上,**单笔不超过 X**,**每天不超过 Y 次**」 |

★★ 好消息:支撑它的三样**产品那一版刚做了** —— **参数确认 · 风险限制 · 修改前后对比**。

#### ★★★ 三条必须守住的

```
★★★ ① **一键停**。他随时能停掉他的 agent,★ 而且**停掉之后已在手的仓位怎么办,
      要在授权那一刻就说清** —— ★★ 不是停了才问他。

★★★ ② **归属照旧**。他的 agent 动手了,流水上要写明是「**他的 agent 按他的规则**」做的,
      ★ 不许记成系统行为,也不许署我们的名(同第三节乙档三条不让)。

★★★ ③ **授权不许续期式默认延长**。★ 到期要他再点一次 ——
      ★★ 「他当初同意过」不等于「他今天还同意」。
```

★ 待定(★★ 不在这一版设计里,但要记下来):**执行失败怎么办**
(下单被拒 · 停牌 · 流动性不足)—— ★★★ 这一格要产品和后端一起定,**不是策略层的事**。

## ★★★ 三秒版

```
★★★ 红线是:我们不替用户下结论。
★★★ 而「主动推送」天生在下结论 —— 一条推送本身就在说「这件事现在重要」。

★★★ 解法只有一句:
     条件引擎不说「你该卖了」,
     它说「**你当初说的那条线,今天碰到了**」。

★★ 所以整个引擎只有一条准入规则:
     **条件必须是他自己的话。不是他的话,一律不许触发推送。**
```

★ 这一句不是口号,它直接决定了引擎能装什么、不能装什么 —— 见第二节那张表。

## 一 · 先把红线那一句说清楚

### 1.1 冲突在哪(大白话)

| | |
|---|---|
| ★ 我们的产品规矩 | **不替他下结论**。给判断的依据,让他自己定 |
| ★★ 助理的本分 | **他不在的时候替他盯着**,到点了叫他 |
| ★★★ 冲突 | 「叫他」这个动作本身**就是一个结论** —— 我凭什么认为这件事值得打断他? |

★★ 而且这个冲突不能靠措辞绕开。★★★ **就算推送里一个「建议」都不写,发出去这个动作已经说了「这事要紧」。**
★ 所以不能在文案层解决,只能在**条件的来源**上解决。

### 1.2 ★★★ 解法:把「判断」这一步整个还给他,提前还

```
★★ 传统做法(会违反红线):
   系统每天看盘 → 系统判断「这个重要」 → 推给他
   ★★★ 判断在系统手里。

★★★ 我们的做法:
   他先说「什么情况下叫我」 → 系统只负责**认**那个情况 → 到了就告诉他
   ★★★ 判断在他手里,而且是**他闲着的时候**做的,不是被叫醒之后匆忙做的。
```

★★★ 这一步换位之后,推送的性质变了:

> **它不是「我们的提醒」,是「他自己的话,到期回到他面前」。**

★ 所以推送的措辞也跟着定死了 —— 第三节。

### 1.3 这一句解开之后顺手解掉的那一半

★★ V3 老师能力里「**复盘 ❌**」那一格,★★★ 条件引擎一上就自动有了原料:

```
★ 每一次「条件触发 + 他当时怎么反应」= 一条复盘记录,自然产生,不用他额外填。
★★ 三个月之后能对他说的话:
   「★ 你设过 7 条线。碰到 5 次。
     ★★ 其中 4 次你按自己说的做了,1 次你改了主意 ——
        改的那次是 3 月 12 日,当时你说『再等等』。」
★★★ 这句话里没有任何评价,全是他自己的记录。
     而这恰恰是「老师」—— ★ 让他看见他自己。
```

| **A2** | ★★ **他自己的 agent 按他定的规则产生的** | 「我的『波段提醒』触发了」 | ✅ **能(走乙档)** | ★★★ 本质还是 A —— 他的规则,只是经过他自己的 agent 一层。★★ 措辞按他的要求(见第三节乙档);★ 归属要写明是**他的 agent**,不许署我们的名 |

| **B2** | ★★ 他绑的策略里,**标「我们填的」的规则** | 「斜率阈值」「宽幅箱体多宽」 | ✅ ★★★ **能 —— 但归属必须显示** | ★★★ **绑定即授权**:他绑了这套做法,就等于同意了这套做法,**包括我们填的那部分**。<br>★★ 唯一的要求是**归属不许藏**:推送里要让他看见「这一条是**我们填的**,不是原著」。<br>★ (Lin 2026-11-04:「★★★ 如果他绑的策略里有的话,就是同意了这个策略,应该提醒啊」) |
| **C** | ★★ 三问里的**物理死线** | 「这笔钱 8 个月后要用」 | ✅ **能** | ★ 这是事实,不是判断。★★ 到期提醒 = 日历,不是观点 |

| **E** | ❌ 我们自己发现的「机会」 | 「这只票形态很好」「这个板块在轮动」 | ❌ ★★★ **永远不能** | ★★★ 这是纯粹的我们下结论,**撞红线正中间** |
| **F** | ❌ 宏观预测 | 「我们认为要降息了」 | ❌ **永远不能** | ★ 已定调:**我们不具备预测宏观的能力,不做宏观预测** |

### ★★ 一条给后端的话

> ★★★ 条件表里**每一条都必须带两个字段**:
> `source` ∈ { **A1 · A2 · B1 · B2 · C · D** },和 `voice` ∈ { **甲档 · 乙档** }。
> ★★ 写不进这个取值集的条件,**引擎必须拒绝创建**,不是警告,是拒绝。
> ★★★ 并且在代码层挡死两件:
> · `source = B2` 的推送,**归属标注字段不许为空** → ★ 空了就**拒绝发送**
>   (★★ 不是拒绝创建条件 —— 条件合法,★★★ 是**不许在不告诉他来源的情况下叫他**)
> · `voice = 乙档` 且要**分享给第三方或上架** → ★★★ **强制切回甲档**(Lin 11-02 定的红线)
> ★ 这些都在代码层挡住,不靠人记得。
>
> ★★★ 另外一条不在引擎里,在**绑定流程**里:
> ★★ 「绑定即授权」成立的前提是**他绑的时候看见了他在授权什么** ——
> ★ 所以绑定那一屏必须显示这套策略的**归属分布**(几条原著 · 几条我们填的 · 几条行业惯例)。
> ★★★ 绑定时没显示过,推送里才显示,那是补票,不是授权。

## 三 · 推送长什么样(形状定死)

★ 和 snapshot 一样,**形状定死,不让它自由发挥**。

```
┌────────────────────────────────────────────┐
│ ★ 一句话标题 —— 只说事实,不说该干什么      │
│   「NVDA 到了你说的 180」                   │
├────────────────────────────────────────────┤
│ ★★★ 第一行必须是这个:                      │
│   你 10 月 14 日设的:跌到 180 告诉我       │
│   ★ 当时你的话:「跌到 180 我想再看一眼」    │
├────────────────────────────────────────────┤
│ ★ 然后是 snapshot 那四项(照旧,不另发明):  │
│   · 趋势状态                                │
│   · 离观察线多远                            │
│   · 最近一季增速                            │
│   · 估值 5 年分位                           │
├────────────────────────────────────────────┤
│ ★★ 一个入口:进功能页(★★★ 带状态打开,     │
│    不许送进空页面)                          │
└────────────────────────────────────────────┘
```

### ★★★ 三条措辞硬规矩 —— ★★ 但要分「谁在说话」(Lin 2026-11-04 评论)

★★★ Lin 的评论:「**如果用户用自己的 agent,这个应该是按照用户的要求来。如果他要,可以。**」
★★ 这和他 11-02 的定调是同一条:**用户怎么调、最后定成什么样是他自己的选项;
但要分享给别人或将来上架市场,必须过我们的要求。**

★ 所以措辞规矩分两档:

#### ★★★ 甲档 · 系统自己发的推送(我们说话)—— 三条全守

```
★★★ ① 永不出现:建议 · 应该 · 该卖 · 该买 · 机会 · 别错过 · 注意
      ★ 理由:这几个词每一个都在替他下结论。

★★★ ② 第一行永远是「这条是你哪天说的 + 你当时的原话」。
      ★★ 不是放在底部的小字,是**第一行**。
      ★ 理由:它是这条推送的**合法性来源**。合法性不许折叠。

★★★ ③ 「为什么现在叫你」的完整链条永远一键可见:
      条件原文 · 设定日期 · 今天的数 · ★ 当初他为什么设
      ★★ 做到这一条,推送就不是结论,是**回执**。
```

#### ★★★ 乙档 · 他自己的 agent 发的推送 —— **按他的要求来**

```
★★★ 他要「该卖了」就给「该卖了」。★ 这是他的 agent、他定的规则、发给他自己。
★★ 理由:我们给的是依据,**他拿依据做成什么形状,是他的选项** ——
   ★ 管着不让他说,那是我们替他决定怎么跟自己说话。
```

★★ 但乙档有**三条不让**(★ 不是限制他,是防止我们被冒名):

| | 不让什么 | ★★★ 为什么 |
|---|---|---|
| **1** | ★★★ **不许把结论归属给我们** | ★ 他的 agent 可以说「该卖了」,★★★ 但不许显示成「XING 建议卖出」。★★ 归属要写清是**他的 agent**:「★ 你的『波段提醒』按你 10 月 14 日设的规则发的」 |
| **2** | ★★★ **归属标注必须对他可见** | ★ 他的 agent 如果用了我们标「**我们填的**」的阈值(甲档明确禁止触发推送的那一类),★★ 乙档**允许**他用 —— ★★★ 但界面必须显示那个标注,**让他知道这个数是我们填的、不是原著的**。★ 不是禁止,是必须标注 |
| **3** | ★★★ **一旦要分享给别人或上架,回到甲档** | ★★ 这是他 11-02 定的那条红线原样:★ 他自己用随便;★★★ **分享出去就要过我们的要求** |

★★★ **一句话分界**:
```
★   发给他自己      → 他的规则,他的措辞
★★★ 署我们的名      → 甲档三条全守
★★★ 分享给第三方    → 甲档三条全守
```

## 四 · 频率和打断(★ 这一节是防止它变成骚扰)

| 条 | 规矩 |
|---|---|
| **1** | ★★★ **同一条条件,他没回应之前不重复叫。** ★ 不是「每天提醒」,是**一次** |
| **2** | ★★ 一天最多几条,**由他定**,默认 **3** 条。★★★ 超过的排队,不是丢掉 —— ★ 但要在队列里告诉他「还有 N 条」 |
| **3** | ★ 物理死线(来源 C)**单独算**,不占那 3 条额度 —— ★★ 因为它是日历,不是观点 |
| **4** | ★★★ 他可以一键「这条别再叫了」—— ★★ 而且关掉之后**要记下来**:哪一条、哪天关的。★★★ 这是复盘的原料,也是对我们的反馈(★ 老被关掉的那一类条件,说明我们形状做错了) |
| **5** | ★★ 条件触发但他**连续三次没点开** → ★★★ 引擎**自己降频**并告诉他:「★ 这类提醒你最近三次都没看,我先降到每周一次,要改随时说」 |

★★★ 第 5 条是这一节的关键:★★ **引擎要能承认自己叫错了**,而不是一直叫。

## 附录 · 为什么说「助理能力不是三分之一」

> ★★★ **这一节 Lin 2026-11-04 确认过**:「★ 说的好,就是这个意思,**三种角色能力的融合**。」
> ★★ 所以下面这个说法不是我的推断,是**他的定义** —— ★ 整份设计都架在它上面,
> ★★★ 以后引用这一段,出处记「Lin 确认」,不是「Claude 推断」。

★★ Lin 的原话:**多重角色的融合 —— 同一句话里三个角色同时在场。**

★ 举他自己的那个例子:

```
「★ 你填的 2% —— 37 套里只有 1 套放得进去」

★ 顾问在场:那个「1 套」是算出来的
★★ 助理在场:它记得他说过 2%
★★★ 老师在场:他从这句话里学到「我的止损上限决定了我能用什么」
```

★★★ **把助理拿掉,这句话就变成「37 套里有 1 套止损宽度 ≤2%」—— 一句正确但与他无关的话。**

★★ 所以条件引擎不是在加一个功能,★★★ 它是在给另外两个角色**装上记忆** ——
★ 而没有记忆,顾问和老师永远凑不成一个人。

★★★ 这也是不做它的代价,V3 文档自己写过:**产品会变成一个你想起来才打开的工具。**
