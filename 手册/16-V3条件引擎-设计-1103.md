# V3 条件引擎 · 设计(2026-11-03)

> 日期:2026-11-03 · 给:Lin 过目 → 后端 / 前端
> ★ 为什么是这一份:V3 三个角色里,专业能力 ✅、老师能力 ⚠ 三分之二、
> ★★★ **助理能力整个上不了** —— 而它卡在一个东西上:**条件引擎**。
> ★★ 而 V3 文档自己写过一句:「**它是唯一一个会让我们违反自己红线的**」。
> ★★★ 这一份的任务就是**把那一句解开** —— 解不开,V3 不该往下走。

---

## ★★★ 三秒版

```
★★★ 红线是:我们不替用户下结论。
★★★ 而「主动推送」天生在下结论 —— 一条推送本身就在说「这件事现在重要」。

★★★ 解法只有一句:
     条件引擎不说「你该卖了」,
     它说「**你当初说的那条线,今天碰到了**」。

★★ 所以整个引擎只有一条准入规则:
     **条件必须是他自己的话。不是他的话,一律不许触发推送。**
```

★ 这一句不是口号,它直接决定了引擎能装什么、不能装什么 —— 见第二节那张表。

## 一 · 先把红线那一句说清楚

### 1.1 冲突在哪(大白话)

| | |
|---|---|
| ★ 我们的产品规矩 | **不替他下结论**。给判断的依据,让他自己定 |
| ★★ 助理的本分 | **他不在的时候替他盯着**,到点了叫他 |
| ★★★ 冲突 | 「叫他」这个动作本身**就是一个结论** —— 我凭什么认为这件事值得打断他? |

★★ 而且这个冲突不能靠措辞绕开。★★★ **就算推送里一个「建议」都不写,发出去这个动作已经说了「这事要紧」。**
★ 所以不能在文案层解决,只能在**条件的来源**上解决。

### 1.2 ★★★ 解法:把「判断」这一步整个还给他,提前还

```
★★ 传统做法(会违反红线):
   系统每天看盘 → 系统判断「这个重要」 → 推给他
   ★★★ 判断在系统手里。

★★★ 我们的做法:
   他先说「什么情况下叫我」 → 系统只负责**认**那个情况 → 到了就告诉他
   ★★★ 判断在他手里,而且是**他闲着的时候**做的,不是被叫醒之后匆忙做的。
```

★★★ 这一步换位之后,推送的性质变了:

> **它不是「我们的提醒」,是「他自己的话,到期回到他面前」。**

★ 所以推送的措辞也跟着定死了 —— 第三节。

### 1.3 这一句解开之后顺手解掉的那一半

★★ V3 老师能力里「**复盘 ❌**」那一格,★★★ 条件引擎一上就自动有了原料:

```
★ 每一次「条件触发 + 他当时怎么反应」= 一条复盘记录,自然产生,不用他额外填。
★★ 三个月之后能对他说的话:
   「★ 你设过 7 条线。碰到 5 次。
     ★★ 其中 4 次你按自己说的做了,1 次你改了主意 ——
        改的那次是 3 月 12 日,当时你说『再等等』。」
★★★ 这句话里没有任何评价,全是他自己的记录。
     而这恰恰是「老师」—— ★ 让他看见他自己。
```

## 二 · ★★★ 条件只能从三个地方来(准入表)

★★ 这张表是整个设计最硬的一部分。★★★ **不在表里的,一条都不许触发推送。**

| | 来源 | 例子 | 能不能推送 | 为什么 |
|---|---|---|---|---|
| **A** | ★★★ **他明确设的** | 「跌到 180 我要知道」「涨 20% 提醒我一次」 | ✅ **能** | ★ 这就是他的话,原样返还 |
| **B1** | ★★ 他绑的策略里,**原著自己写的规则** | 「收盘跌破 145 日线离场」(技-3 原著阶段四) | ✅ **能** | ★★ 他绑定的时候就等于同意了这套规则 —— ★ 绑定即授权,这条我们已经定过 |
| **B2** | ★★★ 他绑的策略里,**标「我们填的」的规则** | 「斜率阈值」「宽幅箱体多宽」 | ❌ ★★★ **不能** | ★★★ 用我们自己填的数去叫醒他 = **我们在下结论**。★ 这是整张表最要紧的一格 |
| **C** | ★★ 三问里的**物理死线** | 「这笔钱 8 个月后要用」 | ✅ **能** | ★ 这是事实,不是判断。★★ 到期提醒 = 日历,不是观点 |
| **D** | ★ 市场级:他绑的打法,**原著写的使用条件**现在不满足 | 「这套原著写明只在牛市中段用」 | ⚠ **原则上能,实际几乎没有** | ★★★ 实测 **44/45 条链的环境开关是空的** —— ★ 所以这一类现在基本触发不了。**不许为了让它能触发而去补条件** |
| **E** | ❌ 我们自己发现的「机会」 | 「这只票形态很好」「这个板块在轮动」 | ❌ ★★★ **永远不能** | ★★★ 这是纯粹的我们下结论,**撞红线正中间** |
| **F** | ❌ 宏观预测 | 「我们认为要降息了」 | ❌ **永远不能** | ★ 已定调:**我们不具备预测宏观的能力,不做宏观预测** |

### ★★ 一条给后端的话

> ★★★ 条件表里**每一条都必须带一个 `source` 字段**,取值只有 A / B1 / C / D 四种。
> ★★ 写不进这四种的条件,**引擎必须拒绝创建**,不是警告,是拒绝。
> ★ 这是在代码层挡住红线,不靠人记得。

## 三 · 推送长什么样(形状定死)

★ 和 snapshot 一样,**形状定死,不让它自由发挥**。

```
┌────────────────────────────────────────────┐
│ ★ 一句话标题 —— 只说事实,不说该干什么      │
│   「NVDA 到了你说的 180」                   │
├────────────────────────────────────────────┤
│ ★★★ 第一行必须是这个:                      │
│   你 10 月 14 日设的:跌到 180 告诉我       │
│   ★ 当时你的话:「跌到 180 我想再看一眼」    │
├────────────────────────────────────────────┤
│ ★ 然后是 snapshot 那四项(照旧,不另发明):  │
│   · 趋势状态                                │
│   · 离观察线多远                            │
│   · 最近一季增速                            │
│   · 估值 5 年分位                           │
├────────────────────────────────────────────┤
│ ★★ 一个入口:进功能页(★★★ 带状态打开,     │
│    不许送进空页面)                          │
└────────────────────────────────────────────┘
```

### ★★★ 三条措辞硬规矩

```
★★★ ① 永不出现:建议 · 应该 · 该卖 · 该买 · 机会 · 别错过 · 注意
      ★ 理由:这几个词每一个都在替他下结论。

★★★ ② 第一行永远是「这条是你哪天说的 + 你当时的原话」。
      ★★ 不是放在底部的小字,是**第一行**。
      ★ 理由:它是这条推送的**合法性来源**。合法性不许折叠。

★★★ ③ 「为什么现在叫你」的完整链条永远一键可见:
      条件原文 · 设定日期 · 今天的数 · ★ 当初他为什么设
      ★★ 做到这一条,推送就不是结论,是**回执**。
```

## 四 · 频率和打断(★ 这一节是防止它变成骚扰)

| 条 | 规矩 |
|---|---|
| **1** | ★★★ **同一条条件,他没回应之前不重复叫。** ★ 不是「每天提醒」,是**一次** |
| **2** | ★★ 一天最多几条,**由他定**,默认 **3** 条。★★★ 超过的排队,不是丢掉 —— ★ 但要在队列里告诉他「还有 N 条」 |
| **3** | ★ 物理死线(来源 C)**单独算**,不占那 3 条额度 —— ★★ 因为它是日历,不是观点 |
| **4** | ★★★ 他可以一键「这条别再叫了」—— ★★ 而且关掉之后**要记下来**:哪一条、哪天关的。★★★ 这是复盘的原料,也是对我们的反馈(★ 老被关掉的那一类条件,说明我们形状做错了) |
| **5** | ★★ 条件触发但他**连续三次没点开** → ★★★ 引擎**自己降频**并告诉他:「★ 这类提醒你最近三次都没看,我先降到每周一次,要改随时说」 |

★★★ 第 5 条是这一节的关键:★★ **引擎要能承认自己叫错了**,而不是一直叫。

## 五 · 后端要建什么(给后端的实话)

★★ 这一节是实现清单,★ 但形状上面已经定死,后端不需要做产品判断。

### 5.1 四个零件

| | 零件 | 干什么 | ★ 要紧的点 |
|---|---|---|---|
| **1** | **条件表** | 存每一条条件 | ★★★ 字段:`谁` · `条件(可执行的表达式)` · `原话(他说的那句)` · `source(A/B1/C/D)` · `设定日期` · `检查频率` · `上次触发` · `触发次数` · `他的反应` · `是否已关闭`<br>★★★ **`原话` 和 `source` 不许为空** —— 空了就不许创建 |
| **2** | **每日扫描** | 收盘后跑一遍,看哪些条件碰到了 | ★ 用现成的那套数,不要另算一套。★★★ **同一行上不许出现两套数据的数**(共用边界 6.15) |
| **3** | **送达层** | 把触发变成一条推送 | ★ 形状照第三节,**模板写死在代码里**,不让模型自由生成 |
| **4** | **带状态打开** | 点推送 → 落在对应功能页,状态已经填好 | ★★★ 这一条是**前端那条任务**(《13》里已派),★ 不做的话推送点开是空页面 —— 硬规矩:**不许把他送进空页面** |

### 5.2 ★★★ 两件事后端千万别做

```
❌ 不要做「智能排序」—— ★★ 按重要性排序 = 我们判断什么更重要 = 撞红线。
   ★★★ 排序只用中性方式:**触发时间**,或**他设定的顺序**。
   ★ 这和首页「排序只用成交额或代码」是同一条规矩。

❌ 不要做「自动合并同类提醒」—— ★★ 合并需要判断哪些算同类。
   ★★★ 要合就按**最笨的方式**合:同一只票的多条条件,列在一条推送里,
      ★ 每条各自写明「这是你哪天设的」。
```

## 七 · ★★ 要 Lin 拍板的(三条,按要紧程度)

### ★★★ 第 1 条 · B2 那一格,确认不许推送

> ★★ 「标**我们填的**」的规则(斜率阈值 · 箱体多宽 · 牛市中段这一类),★★★ **不许触发推送**。
> ★ 代价说清楚:这会让一部分策略**在 V3 里没有提醒能力** —— ★★ 因为它们的关键规则本来就是我们填的。
> ★★★ 我的倾向:**不许**。★ 理由:一旦允许,「我们填的数」就有了打断用户生活的权力,
> 而那个数本来是我们明确标出来「原著没说」的。

### ★★ 第 2 条 · 条件由谁帮他设

> ★ 用户大多不会自己想出「跌到 180 告诉我」这种条件。★★ 所以需要我们**引导**他设。
> ★★★ 但引导到什么程度就越界了?我给两档,★ 你选:
>
> | 档 | 做法 | ★ 风险 |
> |---|---|---|
> | **甲(我的倾向)** | ★★ 我们给**空模板**:「你希望什么情况下我叫你?」+ 三个**类型**例子(价格到某个数 / 某条规则触发 / 某个日期)—— ★★★ 但**不填具体数** | ★ 转化率低,很多人设不出来 |
> | **乙** | ★ 我们按他绑的策略**预填一个数**,他改或确认 | ★★★ 预填那个数就是我们的判断 —— ★ 而且用户大概率直接点确认,等于我们替他定了 |
>
> ★★ 我倾向**甲**。★★★ 理由:乙的「他确认了」是假的同意 —— ★ 默认值的力量太大,这一点我们在「缺省值替我们表态看多」那个 bug 上已经吃过一次。

### ★ 第 3 条 · 第一版装几种条件

> ★★ 我的倾向:**只装 A 和 C 两种**(他明确设的 + 物理死线)。
> ★ B1(原著规则)第二版再上 —— ★★ 理由:B1 要先解决「他绑的策略里哪些规则是原著的」这个标注问题,
> 而那正是《14 第 10 格》还在你手上的那件事。★★★ 先上 A+C,引擎能跑起来、复盘有原料,风险最小。

## 附录 · 为什么说「助理能力不是三分之一」

★★ Lin 的原话:**多重角色的融合 —— 同一句话里三个角色同时在场。**

★ 举他自己的那个例子:

```
「★ 你填的 2% —— 37 套里只有 1 套放得进去」

★ 顾问在场:那个「1 套」是算出来的
★★ 助理在场:它记得他说过 2%
★★★ 老师在场:他从这句话里学到「我的止损上限决定了我能用什么」
```

★★★ **把助理拿掉,这句话就变成「37 套里有 1 套止损宽度 ≤2%」—— 一句正确但与他无关的话。**

★★ 所以条件引擎不是在加一个功能,★★★ 它是在给另外两个角色**装上记忆** ——
★ 而没有记忆,顾问和老师永远凑不成一个人。

★★★ 这也是不做它的代价,V3 文档自己写过:**产品会变成一个你想起来才打开的工具。**
