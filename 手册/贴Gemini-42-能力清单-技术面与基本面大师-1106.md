# ★ 以下是要贴给 Gemini 的正文

---

假设你是华尔街顶级的技术派分析大师。

我们在做一个产品，要让它具备「顶级技术面大师」的能力。我们已经按方法流派建了一批能力，现在要做一次**能力对齐检查**——所以请你先给出清单，我们再逐条对照自己缺什么。

## 一、请给一份能力清单

**请按「用户会来问的事」分组**，而不是按「技术分析包括哪些内容」分组。因为我们要的是「接得住用户的问题」，不是教科书目录。

至少覆盖这五类用户问法（★ 你认为还该加的请加上，并说明为什么）：

1. 「帮我看看这只票现在什么情况」
2. 「我想做突破，该怎么做」
3. 「我想做震荡，该怎么做」
4. 「我现在该把止盈止损放哪」
5. 「我已经持仓了，下一步看什么」

**每一类下面，请逐条列出「必须会什么」，并且每条都给这三样：**

| | 要什么 |
|---|---|
| ① **按什么顺序看** | 第一步看什么、第二步看什么。★ **顺序本身就是知识**，不要只给一堆指标名 |
| ② **能不能落成代码** | 这一步是**算得出来的**，还是**只能靠人眼和经验**？请明确标 |
| ③ ★★★ **凭什么知道** | 为什么是这个顺序、这个阈值？★ 出处是原著（哪本书哪一章）、学术论文（作者+年份+期刊）、行业惯例、还是**你的推断**？ |

```
★★★ 第三样是分流闸,不是客套话:
   · 说得出「凭什么」的 → 我们编码进系统
   · ★★ 说不出「凭什么」的 → 我们挂「外部模型回答·未经测试」这一档,**不编码**
→ ★★★ 所以**请如实标「这是我的推断」** —— 标了我们照样收下,
     只是归另一档;★ 编一个出处反而会让整条作废。
```

## 二、同一套，再给基本面大师一份

假设你是华尔街顶级的基本面分析大师，同样的要求、同样的三样东西。

用户问法至少覆盖：

1. 「这家公司值多少钱」
2. 「这家公司的生意好不好」
3. 「这家公司会不会出事（财务造假 / 债务 / 现金流断）」
4. 「现在这个价格贵不贵」
5. 「我该在什么条件下卖掉它」

## 三、两个问题（★ 请直接回答，不要绕）

**问题 1 —— 哪些能力是「必须会」，哪些是「锦上添花」？**
请把清单里的每一条标上 **必备 / 加分**。★★ 我们要先把「必备」那部分补齐。

**问题 2 —— 哪些能力做不到「可计算」？**
有些东西（比如「这个形态看起来不健康」）本质上依赖经验判断。请明确指出清单里**哪几条落不成代码**，以及**业内在产品里一般怎么处理这几条**（是不做、还是降级成提示、还是让人工复核）。

## 四、我们的边界（★ 告诉你，免得给我们算不出来的东西）

我们的回测和判定引擎目前只有**日线** OHLCV + 成交额，以及在此之上算出来的东西（各种均线、ATR、布林带、肯特纳通道、唐奇安通道、ADX、RSI、相对强度、摆动高低点、箱体边界、区间假突破计数等）。

**我们现在没有的：**
- 分钟级撮合（有分钟数据，但引擎一天只撮合一次）
- 历史时点的行业分类（只有今天的快照）
- 历史股数（所以做不了时点市值）
- 分析师一致预期

**所以如果某条能力必须依赖上面这些，请明确说明**——我们好知道那是「要买数据」还是「要改引擎」，而不是「我们没做」。

## 五、三条硬要求

1. **不要给书里的统计数字。** 前几轮你给过多次精确到小数点的「某本书里的胜率」，我们核过，其中有编造的。凡给数字必须注明是学术论文（作者+年份+期刊）、原著（哪本哪章）、还是你的推断。**没有出处就直接说「这是我的推断」。**
2. **行业没有公认做法的，请直接说没有。** 我们宁可在产品里写「业内没有公认做法」，也不要一个被包装成标准的猜测。
3. **按条列、可勾选。** 我们会把你这份清单做成一张对齐表逐条打钩，所以**每条要能独立成立**，不要写成一段连贯的论述。
