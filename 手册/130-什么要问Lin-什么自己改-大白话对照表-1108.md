### ★★★ B 格要 Lin 定一次的，就这四样（定完能管很久）

```

③ ★★★★★ **承诺的上限** —— 哪些话**一句都不许说**（★ 例：「能跑赢大盘」）

  ★★ Lin 只看体检报告。

### ★ 怎么分清「骨架」和「细节」（★★ 这是最容易混的一处）

```

## 一、★★★ A 格怎么判（★ 一句话规矩，★★ 只管 A 格）

```
★★★★★ **改完之后，同样的问题问系统，它会不会给出不一样的答案？**

   · 会  → ★★★ **要问 Lin**
   · 不会 → ★ **自己改，不用问**
```

★ 再说细一点，「不一样的答案」只看三件事：

```
① ★★★ 选出来的**股票**会不会变？
② ★★★ 给出的**买 / 卖 / 继续拿着**的结论会不会变？
③ ★★★ 原来**能通过**的会不会变成**通不过**（或者反过来）？

→ ★ 三个里**只要有一个会**，就是要问 Lin 的事。
→ ★★ 三个**都不会**，就是你自己的事，直接改。
```

```
★★ 为什么是这三件：因为这三件一变，★★★ 我们之前所有的回测成绩**全部作废**，
   ★ 要重跑一遍才知道新的数是多少。★★ 那不是「优化」，是「重做一轮」。
```

## 二、对照表（★ 直接找你要改的那一类）

### 2.1 ✅ 这些**自己改**，不用问

| 你要改的 | 为什么不用问 |
|---|---|
| 把一段话说得更短、更顺 | ★ 答案不变 |
| 换一个举例的公司 | ★ 答案不变 |
| 调整提问顺序（先问目标还是先问风险） | ★ 最后结论一样 |
| 加一句解释，告诉用户这个指标是什么意思 | ★ 不影响判断 |
| 把表格改成列表、把列表改成表格 | ★ 只是呈现 |
| 补一个常见问题 / 补一句提示 | ★ 不改规则 |
| 修错别字、统一术语叫法 | ★ 本来就该改 |
| 界面上按钮位置、K 线怎么显示、交互怎么走 | ★ 不碰判断 |

### 2.2 ⛔ 这些**必须问 Lin**

| 你想改的 | 为什么要问 |
|---|---|
| 改任何一个**数字门槛**（市盈率 15 → 20、成交额 1000 万 → 500 万） | ★★★ 选出来的股票变了 |
| 加一条**新的筛选条件**（哪怕看起来很合理） | ★★★ 原来能过的会变成过不了 |
| 删掉一条现有条件 | ★★★ 同上，反方向 |
| 改**什么时候买 / 什么时候卖**的规则 | ★★★ 买卖结论变了 |
| 改**排序方式**（按什么排前后） | ★★ 推荐出来的顺序变了 → 用户看到的不是同一批 |
| 改**几只、几档、几天**这类数量（持仓 6 只 → 10 只） | ★★★ 结果变了 |
| 把「可能」改成「大概率」、把「不建议」改成「建议谨慎」 | ★★ **对外口径** —— 这是我们对用户的承诺强度 |
| 写任何一句**成绩 / 收益 / 胜率**的话 | ★★★ 对外口径，而且要有数支撑 |
| 动 `common_boundaries.md`（共用边界） | ★★★★★ **28 个 skill 共用它**，改一行等于改 28 个 |

### 2.3 🟡 拿不准的时候

```
★★★ **拿不准 → 当成要问。** ★ 宁可多问一次。
★★ 判断方法：你心里如果冒出「这样改应该更合理吧？」——
   ★★★ 「更合理」就说明你在**改判断**，那就是 Lin 的事。
★ 反过来，如果你想的是「这样说用户更容易懂」——那是你的事，直接改。
```

## 三、怎么问（★ 不要一条一条来）

```
★★★ 每个组开一张「**要问 Lin 的清单**」，★ 遇到就记上，**不要当场打扰他**。
★★ 每轮**固定一次**（建议周二）一次性过完 —— ★★★ 他一次答完，大家一次清空。
★ 清单每条写三样就够：
   ① 我想改什么（一句话）
   ② 为什么想改（一句话）
   ③ 我猜改了会影响什么（★ 猜错没关系，写出来 Lin 一眼就能判）
```

```
★★ 为什么要攒：★ Lin 还要做策略研究，★★★ 被零碎问题切成碎片，
   那部分活就做不动了 —— ★ 而那部分没人能替。
```

## 四、Lin 这边答什么（★ 他只答两类）

```
★★★ ① **判据**：门槛、条件、买卖规则、数量、排序 —— ★ 这些只有他能定。
★★★ ② **对外口径**：成绩怎么说、风险怎么说、承诺到什么程度。
★★ 除这两类以外的，★★★ 他不看、也不用看 —— ★ 那是各组自己的活。
```

```
★★★★★ 一句话总结给 Lin：
   **你守的是「判断有没有被动」，不是「这张卡写得好不好」。**
```
