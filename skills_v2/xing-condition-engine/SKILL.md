# 条件定义与确定性判定

## 目标
把明确的条件表达式变成一致、可解释、可复核的判定结果，作为筛选、复检与监控的底层规则契约。条件引擎只能根据确实可用的数据判断，不得以语言模型直觉补齐数值。

## 权责分离
- 本技能只做：条件标准化、逻辑校验、字段核对、结果判定、失败与未知说明。
- `xing-screener` 决定股票池和候选展示；`xing-skill-builder` 负责通用规则的创建与验证阶段；`xing-agent-builder` 负责具体实例配置和权限；`xing-review` 负责持仓决策场景。
- 条件引擎不自行检索全市场股票池、不自我保存规则、不承诺后台持续运行、不下单、不创造不存在的计算后端。

## 条件规范化
每项规则必须记录：`rule_id`、`rule_version`、`subject`、`metric`、`operator`、`value/threshold`、`unit`、`timeframe`、`window`、`source`、`as_of`、`missing_policy`；复合规则还需 `logic_tree`。
标准运算符统一为 `>`、`>=`、`<`、`<=`、`==`、`!=`、`between`、`cross_above`、`cross_below`；若输入使用单个 `=` 代表相等，先显式规范化为 `==` 并在规范化规则中留痕。不得把 `=` 当赋值语句或混用为不等于。“大于”和“大于等于”不可互换。区间须明确是否包含边界，百分数与百分比变化、元与万元、季度与滚动十二个月不得混用。
自然语言“最近、稳定、明显放量、低估值”等含糊词需要给出可选定义或要求补充，不得假装天然有一个唯一阈值。

## 数据与计算
1. 验证输入数据的归属、版本、时间、币种/单位、复权、报告期与来源是否满足规则。跨证券、跨时点、跨货币数据未经标准化不可比较。
2. 指标若需要时间序列，应检查窗口样本完整性；财报 TTM、同比和滚动指标需原始期间齐全；缺一项不得捏造。
3. 执行比较仅基于明确数据及确定性算式。若外部计算器或正式引擎不存在，允许处理用户提供的少量可审计数据，但禁止声称已由后端执行。
4. 结果实行四状态：`TRUE` 已证实满足；`FALSE` 已证实不满足；`UNKNOWN` 因缺数据、来源失效或时点不能对齐而无法判断；`INVALID` 表示规则本身不合法、类型冲突、字段无定义或运算符不支持。必须先全局校验规则是否合法，再计算真值。
5. 合法规则按强 Kleene 三值逻辑处理：`AND` 有一个 `FALSE` 则结果为 `FALSE`，全 `TRUE` 才为 `TRUE`，其余 `UNKNOWN`；`OR` 有一个 `TRUE` 则为 `TRUE`，全 `FALSE` 才为 `FALSE`，其余 `UNKNOWN`；`NOT UNKNOWN = UNKNOWN`。规则表达式中如有 `INVALID` 子句，**校验阶段整体返回 `INVALID`**，不得以 TRUE/FALSE 的短路掩盖非法子句。
6. 绝对禁止把 UNKNOWN 当 FALSE、把没有触发的监控解释为已验证未触发、把未执行当作执行成功。

## 版本与追溯
任何阈值、窗口、指标定义变化均形成新的 `rule_version`。结果必须记录相应规则版本、输入快照时点、数据覆盖、计算依据和 `evaluation_status`，不得用新版条件重新解释旧版日志而不标注。

## 输出
首轮优先给可读的规范化条件；若数据完整则提供逐条真值及原因，并呈现总条件判断；数据不足则具体列出缺口。不要对外输出工具内部执行日志、推理过程或实现细节。

## 自检
指标定义一致？单位一致？时间窗口完整？运算边界准确？未知没有误当失败？所有结果均有版本、时间与证据？

参考：`references/shared/common_boundaries.md`、`references/field_contract.md`、`templates/response.md`。

## 明确的运算语义
- **顺序与优先级**：必须显式解析 `logic_tree`；没有括号或结构的混合 AND/OR 表达式须说明采用的优先级，若有歧义先返回草案而不是悄悄改变含义。
- **数值比较**：整数/小数比较基于来源允许的原始有效精度；不得先把 `10.004` 显示为 `10.00` 再判断 `> 10`。对负数、零、百分数（`0.12` vs `12%`）、百分比变化和百分点差异需对齐口径。
- **区间**：`between` 必须声明端点开闭，例如 `[10,20)`；不得隐含等号，区间下限大于上限应判 `INVALID`。
- **穿越**：`cross_above` 为上一已完成周期 `左侧指标 <= 上期对应阈值` 且当前已完成周期 `左侧指标 > 当期对应阈值`；`cross_below` 为上一已完成周期 `左侧指标 >= 上期对应阈值` 且当前已完成周期 `左侧指标 < 当期对应阈值`。若阈值是均线等动态序列，必须对齐两期各自阈值，不能将当前均线值回填到上期；是否允许盘中触发须单独配置。
- **派生数据**：已定义合理的公式在某条数据中遇到分母为零、不可用/非数值或来源不确定时，须在**实际执行后**输出 `UNKNOWN` 并说明原因；公式本身逻辑错误、运算符不支持或阈值类型不合法则在校验阶段 `INVALID`。不存在的字段不默认为零。
- **时间可得性**：价格以交易阶段/时区确定有效时间；财务数据以真实公告公开时点确定可用性，回看不得拿尚未披露的报告计算。
- **状态分离**：`validation_status`（规则是否合法）、`evaluation_status`（是否真实执行）、`condition_result`（判定真值）分别记录；“未执行”不等于 `FALSE` 或 `UNKNOWN` 的已执行判定。

## 规则校验与执行状态的不可混淆项
- **规则含糊**（例如“走势较强”但没有可计算口径）：`needs_clarification`，输出规范化候选定义；不能作为已执行 `UNKNOWN`。**规则非法**（例如字符串与数值作大于比较，未支持的运算符）：`INVALID`，停止计算。
- **规则合法但没有计算工具/没有实际发起计算**：`not_evaluated` 或 `blocked`，不填写 `TRUE/FALSE/UNKNOWN`。**规则已执行但单条数据缺失**：该行 `UNKNOWN`，与部分条件的 TRUE/FALSE 共同按真值逻辑汇总。
- 历史资料只能用于已公开的时点：回看需校验财报公开日期、证券历史成分、有效交易日和调整口径。布尔逻辑确定性不等于数据真实性。
