## 1  这个 Skill 管什么

让用户定义自己的筛选条件、自己的提醒规则,并对它们做检验。

★★★ **而这张卡真正的工作不是「帮他做出来」，是「如实告诉他它有多可能是巧合」。**

## 2  什么时候用

★ 用户原话（★★ 共同特征：**他要的是一条可复用的规则，没有具体标的**）：

- 「我想做一个自己的筛选」
- 「找**所有**跌破 20 日线而且缩量的」
- 「帮我做一个规则：放量突破 60 日新高就提醒我」
- 「我想试试：RSI 低于 30 而且在 200 日线上方」
- ★★ 「我按我自己那套办法筛，能筛出几只？」

```
★★★ 分流判据(★ 唯一一条机械判据):**他说的里面有没有具体标的。**
   **没有标的** → 他要一条可复用的规则 → **这张卡**
   **有标的**   → 他要一个实例 → `xing-agent-builder`
★★ 用户永远不需要知道这两个词 —— 入口统一,底下分流。
```

## 3  不管什么,交给谁

- 替他定义 → 不管（★★ 规则必须是他自己定的，见第 6 节第五条）
- 评价某只股票 → **行情 / K线互动**
- 盯**某一只**票 → **创建 / 编辑 agent**

## 4  这个场景属于哪一档

**搭工具。主动。**

★★ 但有一个例外：★★★ **谈检验结果的时候转回「克制」** —— ★ 参数怎么配可以给建议，
★★ 「这条规则行不行」**不许给结论**，只报它在哪里会坏。

## ★★★ 5  输出长什么样

### 5.0 整条路

```
   ① 把他的话变成一条看得懂的规则
      ★★ 给他看一遍:「我理解你要的是 ——」
                │
   ② 在**他能看到的那段数据**上跑 → 出结果
      ★ 他想怎么调就怎么调,**不限次数**
                │
   ③ ★★★ 每次调完,显示**调参次数 + 那句话**(见 5.2)
                │
   ④ 他点「**正式验收**」
                │
   ⑤ ★★★ 系统在**封存的那段数据**上**只跑一次** → 结果照实给他
      ★★ 同一个版本**只能验收一次**;改了参数就算新版本
```

### ★★★ 5.1 两段数据 —— 这一节是整张卡的核心（★ Lin 2026-11-03 拍板）

| | 他能看到的那段 | ★★★ 封存的那段 |
|---|---|---|
| **他能不能看** | ✅ 能 | ❌ ★★★ **不能，一眼都不行** |
| **能调几次** | ★ **随便调，不限次数** | — |
| **跑几次** | 每次调完都跑 | ★★★ **每个版本只跑一次** |
| **结果** | 照实给 | ★★★ **照实给，不通过就是不通过** |

```
★★★ 为什么是这个机制,而不是「加一个警告」:
   ★ 警告**会被学会无视** —— ★★ 散户在回测工具里的心理诉求是找印证,
     ★★★ 静态的提示字出现两次之后就被大脑过滤掉了。
   ★★★ 而**封存那段数据是绕不开的** —— ★ 他调一百次也改不了
      「它在没见过的数据上表现怎样」这件事。
★★ 而这**不违背**「不限制他调」那条原则:
   ★ 他在能看到的那段上**照样随便调**;系统只是**如实告诉他**
     这条规则在它没见过的数据上长什么样。
```

★★★ **封存段的工程口径**（★ 技术组定，我们给要求）：

```
★ 建议:**用最近的一段**,★★ **所有用户共用同一个封存段**,
  ★★★ 数据往后滚动更新时,封存段**也跟着往后挪**。
★★ 三条硬要求:
   ① 封存段**任何界面都不许泄露** —— 包括图表的 x 轴范围、
      「数据截止到 X」这类文案。
   ② ★★★ **验收次数要记下来**(按「用户 + 策略族」累计)——
      ★ 一个用户把同一条规则改 20 个版本、各验收一次,
        ★★ 那等于在封存段上跑了 20 次,**这件事必须看得见**。
   ③ ★ 封存段往后挪的时候,**旧的验收记录不作废** ——
      ★★ 它记的是「他当时试了多少次」,那是行为记录,不是成绩。
```

### ★★★ 5.2 调参次数怎么显示（★ 不显示任何概率）

```
┌─────────────────────────────────────────────────────┐
│ ⚠ 这条规则已在这段数据上调了 **17 次**。              │
│   参数调得越细,回测结果越可能只是巧合。               │
└─────────────────────────────────────────────────────┘
```

| | |
|---|---|
| ★★★ **不许显示任何概率** | ★ 包括「由运气拼凑的概率 58.2%」「有效独立尝试 2.3 次」这类 |
| ★★ **为什么不显示** | ★★★ 现成那个公式（`1-(1-0.05)^N`）**假设每次调参互相独立** —— ★ 而调参**高度相关**（20 日改成 19 日，两次用的几乎是同一批数据、同一个信号）。★★ 所以那个数是**高估**的；★★★ 而在界面上显示一个**错的概率，比什么都不显示更糟** —— 它看起来很精确 |
| ★ **次数怎么累计** | ★★ 按「**用户 + 策略族**」累计 —— ★★★ **删掉重建不归零**（★ 绑在实例上会被绕过） |

## 6  这个 Skill 特有的禁令 —— 这是八张里最危险的一个

**为什么最危险:**用户在这里定义的东西会被系统执行,而且他会把它当成「经过验证的」。

**他会把我们给的检验工具当成背书工具用** —— 不断微调参数,直到系统显示「通过」。
那叫更高一层的过拟合,**而且他自己不知道。**

### ★★★ 五条防护，一条都不能省

**一、不让用户自己选对照组。**
「换一只同类股票测测」不能由用户在搜索框里输入 —— **必须系统从行业池随机抽**,
后台跑完再呈现。否则他会一直换到某一只翻红为止,然后截图自证。

**二、先看死因,再看存活。**
首屏第一行必须是最惨的那一组:参数挪动后收益最差的、起点挪动后回撤最深的。
**禁止展示绿色打勾清单。**

**三、措辞里不许出现正向背书。**

| 不能这么说 | 要这么说 |
|---|---|
| 恭喜!策略通过了参数敏感度测试 | 参数脆弱度:在这组参数边缘,有 X 处结果断崖下跌 |
| 跨标的验证成功,具备泛化能力 | 样本外未被证伪:随机抽取的标的上暂未穿透,不排除幸存者偏差 |
| 回测健康度 85 分(合格) | 过拟合排查:尚未排除虚假共振(只完成初级压力测试) |

**第三行那个「85 分」正好撞共用边界里「不做综合评分」那条** ——
所以这张表不只防用户误用,也是我们自己的红线。

★★★ **四、永远不出现「通过 / 已验证 / 合格」这种状态。**（★ 2026-11-03 新增）

```
★★ 理由很直接:**没有「通过」这个状态,就没有东西可以被他当成背书。**
★ 所以界面上只有两种东西:
   ① **它在哪里会坏**(参数脆弱度 · 起点敏感度 · 对照组不一致)
   ② **它在没见过的数据上长什么样**(验收那一次的数)
★★★ 两种都**只报数,不下结论**。
```

**五、自研规则的归属标注是 `我们 · 实证`,要配一张实证卡。**
实证卡含:测试标的全集、样本内外分割点、交易笔数、显著性、参数敏感度。
**严禁套用任何大师的名字。**

★★★ **六、改规则必须说出后果。**（★ 2026-11-03 新增 —— 原来只有 agent 那一侧写了）

```
★ 他改一条规则的时候,要说清**改了之后什么跟着变**:
   「把成交量条件从 1.5 倍放宽到 1.2 倍 →
     ★★ 触发次数从 41 次涨到 **118 次**,
     ★★★ 而参数脆弱度那一项**多出 3 处断崖**。」
★★ 而且:★★★ **改了参数就算新版本** —— 封存段的验收次数**重新记一次**。
```

## ★★★ 6附 · 一件必须让用户知道的事（★ 2026-11-03 新增）

> ★★ 说明书 / 第一次进这个功能时，★★★ **第一句话就要写这个**：

```
╔══════════════════════════════════════════════════════════╗
║  ★★★ **这套检验不会提高你这条规则的胜率。**                 ║
║     它只告诉你:**这条规则会在哪里坏掉**,                   ║
║     以及**它在一段你没看过的数据上表现怎样**。              ║
╚══════════════════════════════════════════════════════════╝
```

```
★★★ 为什么要把这句话放在最前面 —— ★ 因为它是**真的**:
   ★★ 一套检验工具**筛不出不存在的东西**。
   ★★★ 而更糟的是:**有了检验工具,用户反而会加大仓位** ——
      ★ 他会产生「我的规则已经被检验过了」的安全感。
   → ★★ 所以这句话**不是免责声明,是这个功能唯一诚实的说明**。
★ 而「它会在哪里坏掉」**是有用的** —— 那才是我们真正能给的东西。
```

## 验证的四样底线（不可由用户关闭）

用户可以定「什么算好」：门槛多高、看哪个指标、要多少笔、能接受多大回撤、看多长的历史。
这些是他的偏好，由他定。

下面四样是「怎么验」，不是偏好。**任何档位都不得关闭、不得由用户指定、不得跳过。**
理由只有一句：这四样一旦可关，他拿到的数字就不再有意义，而他不会知道。

### ① 样本外区间：只有一次机会

历史数据切两段。前段供反复试，后段在确认之前不得参与任何计算、不得用于挑选参数。
用户说「调好了」，后段才跑，**且只跑一次**。跑完即失效；要再验，只能换一段他未见过的区间。

- 后段结果不得反向用于改参数。若改了参数，必须重新取一段未使用过的区间，并说明原区间已失效。
- 没有可用的未见区间时，状态为「无法做样本外检验」，不得以样本内结果代替。

### ② 对照组：由系统随机抽取，用户不得指定

同一套规则，除目标标的外，另在系统随机抽取的同类标的上运行一遍，用于区分
「规则有效」与「只在这一只上有效」。

- 抽取由系统完成。**不接受用户输入、指定、替换或重抽对照标的。**
- 对照组结果与目标结果必须同屏并列，不得只显示其中一个。
- 对照组上不成立时，结论写「样本外未被证伪」，不得写「已验证」「具备泛化能力」。

### ③ 参数脆弱度与起点敏感度

- **参数脆弱度**：用户给的每个数值门槛，同时跑它上下各一档（相邻两点），
  报三点是否同向。只有中间那点成立 = 该门槛对上了这段历史，不是规律。
  相邻两点的间距由用户给的门槛本身决定，不由我们预设。
- **起点敏感度**：同一规则换若干个起始日各跑一遍，报结果离散程度。
  换起点就变样 = 结果取决于起跑日的选择。
- 两项都必须出数。算不出来时写「算不出来」，**不得与「分数差」混成一个数**。

### ④ 调参次数计数器

同一条规则从建立到当前的修改次数，**在结果页面明文显示**，例：已调 N 次。

- 计数不得清零、不得隐藏、不得折叠。
- 调参次数本身不构成拦截，但必须与结论同屏：调了很多次才通过与第一次就通过，不是一回事。

### 三档：谁定标准（Lin 2026-11-09 拍板）

| 档 | 门槛由谁定 | 用在哪 | 上面四样 |
|---|---|---|---|
| 自定 | 用户自己的规矩 | 自己看、自己用 | 照常全跑、全显示 |
| 默认 | 我们这一套 | 用户没有自己的规矩时 | 照常全跑、全显示 |
| 过审 | **只能是我们这一套** | 要分享给他人、要上架 | **全跑、全显示，且不可关** |

三档的差别只在「门槛谁定」，不在「要不要验」。四样在三档里都不可关闭。
